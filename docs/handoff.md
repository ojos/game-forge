## 1. 現在地

**生成パイプラインは 6 段すべてが結線され、本番で開通しています。**

```
/generate（画面）→ クォータ判定 → 生成 → 費用計上 → import 検査
  → ビルド → [機械修正（費用ゼロ）→ LLM 再生成 ×2] → R2 → games（draft）
```

段ごとの実装と経緯は仕様書 1.2.31〜1.2.37 に、進捗の全体像は
[mvp-roadmap.md の「進捗」](mvp-roadmap.md) にあります。

## 3. 触るときの注意

- **生成経路は課金されます。** サブエージェントには「`/api/generate` を実際に呼ばない」と
  明示すること。テストは経路層のハンドラを直接叩きます
- **Bedrock の鍵は Active です。** 止めるなら
  `aws iam update-access-key --user-name game-forge-bedrock-invoker --access-key-id <id> --status Inactive`
- **本番 D1 への書き込みは拒否されることがあります**（実行環境の判定）。都度の承認を得ること
- **AWS SSO は切れます。** `aws sso login --profile game-forge-prod --use-device-code`
- **GCP の ADC も切れます。** `gcloud auth application-default login --no-launch-browser` のあと、
  **必ず `ido@ojos.jp` であることを確認**すること。別アカウントでも認証は成功し、
  `terraform plan` が権限エラーになるまで気づけません（[gcp-oauth-setup.md](gcp-oauth-setup.md)）
- **仕様の古い記述は削らず、注記を足して残します**
- **マージは squash のみ。利用者の明示的な指示があるまでマージしません**

## 4. 並列作業のやり方

worktree とサブエージェントで **3 レーンまで同時に走らせて成立しました**（2026-08-28）。
衝突したのは仕様書の版行と節番号だけです。

- **所有ファイルを重ねない。** レーンごとに明示して渡す
- **`docs/product-spec.md` の版行 2 行は誰にも触らせない。** 取り込む側が版と節番号を付ける
- **マイグレーションの連番は先に割り当てる**（`0004_` は誰、`0005_` は誰）
- **worktree を消さない。** 消すとレビュー指摘の差し戻しができなくなります
- **レビュー指摘は書いた本人へ差し戻す。** 変異検査の型を持っているので直りが速く、質も高い
- **同じ継ぎ目を 2 レーンが触る場合は、結線だけを最後の 1 本にまとめる**
  （`defaultPipeline` は 4 行のオブジェクトで、2 レーンが同時に足すと必ず衝突します）
