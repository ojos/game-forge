## 3. 1 日目が終わったらやること

**2 日目の構成は、1 日目の実測で決め直します**（#43）。1 日目に測るのは次の 3 つです。

1. **実際のソース量**（64KB に対する余裕）
2. **所要時間**（1 本あたり。**送信から完成までの実測は 107 秒**——ただしこれは 2026-08-30、
   64KB へ上げる前の値である。時間予算の現行値は仕様 4.4 を見ること）
3. **費用**（`docs/usage-report.md` と `scripts/usage-report.sh`）

**6 がモデレーションで落ちた場合は、仕様 8.2 の実測表へ 1 行足してください**（暴力・不品行の
フィルタを外した v1.47 以降で落ちた初の記録になります）。

## 7. 生成品質の基準線（2026-09-16 / #597）

**この 10 本は、生成品質を測るための基準線として使える。** お題の文面（2 章）が残っており、
作品 id も 6 章にあるので、**同じお題で生成し直せば前後を比べられる。**

**生成は 1 回も回していない**（本番は D1 と R2 の読み取りだけ）。R2 の `source.go` を 10 本
取り出し、構文だけで数えた。バイト数は 6 章の表と全件一致する。

### 測り方

**型情報を使わず `go/parser` の構文木だけで数える**（生成物は 1 ファイルなので足りる）。

- **読まれないフィールド**: 構造体のフィールド宣言を集め、`x.Field` の出現を「素の代入（`=` の
  左辺）と複合リテラルのキー」「自分の値だけを更新するもの（`++` / `+=`）」「それ以外（読み取り）」
  へ分ける。**読み取りが 0 回のものを数える。** `g.score++` だけで一度も読まれないフィールドは、
  加算しているのに画面へ出していないことを意味する
- **勝ち・負けの表示**: 文字列リテラルを集め、勝ちの語（クリア / かった / しょうり / ゴール /
  おめでとう …）と負けの語（ゲームオーバー / まけ / やられた …）を含むものを拾う
- **色数**: `color.RGBA{…}` の複合リテラルを、引数の並びで重複を除いて数える
- **スプライト**: `ebiten.NewImage` の呼び出し回数

**語の一覧は取りこぼす。** 最初の一覧は「かち」を持っていたが「かった」を持たず、6（ケロケロ
舌合戦）の `かった！` を見落として「勝ちは 4/10」と出した。**この指標は下限であり、上限ではない。**

### 測り直すとき

**#597 のプロンプト変更は、この基準線と比べていない**（効果の実測を受け入れ条件から外した。
利用者の決定 / 2026-09-17）。次に本番で生成する機会に、**2 章のお題をそのまま使って**測り直す。

**#605 で、測るのは機構の仕事になった。** 生成のたびに `source_quality_metrics` へ残るので、
手で数え直す必要はない（仕様 6.1「生成物の質を測る」）。**この表の値も、埋め戻し
（`bash scripts/source-quality-backfill.sh --remote --apply`）で同じ実装から測り直す**——
上の値は使い捨ての Go の道具で測ったものなので、**測り直さないと違う物差しで前後を
比べることになる。**

**ただし、機構が測るのは 5 列のうち 4 列である。**

| 列 | 機構が測るか |
|---|---|
| 勝ちの表示 / 負けの表示 | 測る |
| 色数 | 測る |
| `ebiten.NewImage` | 測る |
| **読まれないフィールド** | **測らない** |
| （新設）`iota` の状態の数 | 測る（この表には無い列） |

**「読まれないフィールド」を落とした理由**は 2 つある。**この指標は「効かない UI」の証拠に
ならない**（上の「読み取れること」のとおり、3 えらべるサカナは装備が実際に効いていた）。
そして**正規表現では正確に数えられず、Go の AST が要る**——置き場所としてはビルド関数が
自然だが、あちらの契約を変えることになる。**この 1 列だけは、必要になったら手で数える。**
