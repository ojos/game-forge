## 1. 現在地

### D1 で FTS5 は使えます。ただし**既定の tokenizer では日本語の部分語が引けません**（#370。2026-09-12）

**結論: 使える。** `create virtual table ... using fts5(...)` は**ローカルでも本番の D1 でも通りました**。
**ただし既定の tokenizer（unicode61）では日本語の部分語検索が成立しません**——題を丸ごと打てば
当たりますが、**「ゲーム」のようなキーワードでは 1 件も返りません**。`trigram` に替えれば
部分語で引けますが、**2 文字の語が `match` で 1 件も返らない**という別の穴が開きます。
**確認タスクなのでコードは 1 行も変えていません**（`migrations/` にも何も足していません）。

#### 実測（すべて `wrangler d1 execute`。本番は `--remote --env production`）

| 確かめたこと | ローカル | 本番（`game-forge` / `d81a6f80-…`） |
|---|---|---|
| `create virtual table ... using fts5(title, body)` | **通る** | **通る** |
| `tokenize='trigram'` 付き | **通る** | **通る** |
| `content='...'` の外部コンテンツ表 + 同期トリガ | **通る**（トリガ 3 本: insert / update / delete） | **通る**（トリガ 2 本: insert / delete） |
| `insert into <fts>(<fts>) values ('delete')` | **通る** | **通る** |
| `insert into <fts>(<fts>) values ('rebuild')` | **通る**（マイグレーション内で実行） | 未実行（本番へ恒久的な索引を作らないため） |
| `drop table` / `drop trigger` で落とせる | **落ちた** | **落ちた**（`sqlite_master` に残骸なし） |
| `vacuum` | **拒否される**（`cannot VACUUM from within a transaction`） | **未実行**（読み取りと使い捨て以外を本番で回さないため） |

打ったコマンドの形はこの 2 つだけです。

```bash
# ローカル（使い捨ての --persist-to。手元の .wrangler/state は汚していない）
npx wrangler d1 execute DB --local --persist-to <tmp> --json --command "<SQL>"
# 本番
npx wrangler d1 execute DB --remote --env production --json --command "<SQL>"
```

**本番に作った使い捨ては 6 オブジェクト**（表 `probe_fts5_370` / `probe_tri_370` / `probe_base_370` /
`probe_base_fts_370`、トリガ `probe_base_ai_370` / `probe_base_ad_370`）**で、すべて `drop` 済みです。**
`select type, name from sqlite_master where name like '%probe%' or name like '%370%'` が
**`[]`（空）** を返すことを最後に確認しました。**既存の表へは 1 行も書いていません**
（読み取りの `changed_db` はすべて `false`）。

#### 日本語（ここが最大の論点でした）

**既定の tokenizer は、空白で区切られない日本語を 1 語として扱います。** 「ブロック崩しゲーム」は
**丸ごと 1 トークン**になり、部分語では当たりません。

| 索引の中身 | 問い合わせ | 既定（unicode61） | `trigram` |
|---|---|---|---|
| `ブロック崩しゲーム` | `match 'ゲーム'` | **0 件** | **当たる** |
| `ブロック崩しゲーム` | `match 'ブロック'` | **0 件** | **当たる** |
| `ブロック崩しゲーム` | `match 'ブロック崩しゲーム'` | 当たる | 当たる |
| `ブロック崩しゲーム` | `match 'ブロック*'` | 当たる（前方一致だけ） | 当たる |
| `宇宙シューティング` | `match '宇宙'`（**2 文字**） | 0 件 | **0 件** |
| `宇宙シューティング` | `like '%宇宙%'`（trigram 表） | — | **当たる** |
| `Puzzle Game Deluxe` | `match 'puzzle'` | 当たる | 当たる |

- **`trigram` は 3 文字未満の語を索引しません。** 「宇宙」「迷路」「将棋」「探索」のような
  **2 文字の語は `match` で 1 件も返りません**——これは 0 件ではなく**黙って外れる**ので、
  画面から見ると「その作品は存在しない」と読めます。**日本語の検索語として 2 文字は珍しくありません。**
- **`trigram` の表は `like '%…%'` を受け付け、2 文字でも正しい行を返します。**
  **ただし「返る」ことと「索引が効く」ことは別です**（下の「`L0` は索引の証拠ではありません」）。
  また `like` は**列ごと**なので、`match` のように複数列をまとめて引くことはできません。
- `rank` での並べ替えと `highlight()` は**どちらも動きました**。

#### `EXPLAIN QUERY PLAN`

```
match（trigram 単体表）        SCAN probe_tri VIRTUAL TABLE INDEX 0:M2
match（trigram 外部コンテンツ） SCAN f VIRTUAL TABLE INDEX 0:M1 | SEARCH g USING INTEGER PRIMARY KEY (rowid=?)
like（trigram / 3 文字以上）   SCAN games_fts VIRTUAL TABLE INDEX 0:L0
like（trigram / 2 文字）       SCAN games_fts VIRTUAL TABLE INDEX 0:L0
素の games を like            SEARCH games USING INDEX games_status_published_at_idx (status=?)
```

**`match` は索引が効きます。** `M2` は fts 表を単体で引いたとき、`M1` は外部コンテンツ表を
本体に join したときの出力で、**どちらも実測した文字列です**。
**素の `games` を `like` で引くと、`status` の索引で公開分に絞ったあと、その全部の `title` を読みます。**

##### `L0` は索引の証拠ではありません

**`L0` は「`like` の条件が仮想表へ渡された」ことしか意味しません。** 実際に索引で絞れるのは
**パターンに 3 文字以上の連続がある場合だけ**で、`L0` は 2 文字でも同じように出ます。
**同じ `L0` でも中身が違う**ことを、同じ表・同じ行数で測って確かめました。

| 問い合わせ | `EXPLAIN QUERY PLAN` | 1 回あたり |
|---|---|---|
| `like '%虹色迷宮%'`（**4 文字**） | `L0` | **0.04 ms** |
| `like '%虹色%'`（**2 文字**） | `L0` | **1.77 ms** |
| `match '虹色迷宮'`（4 文字） | `M1` | **0.04 ms** |

**2 文字の `like` は 44 倍遅く、母数に比例します。** **`EXPLAIN QUERY PLAN` の字面だけで
「索引が効いている」と判定しないこと。**

#### 母数が増えたときの壊れ方（ローカルに 20,002 行入れて実測）

| 経路 | 1 回あたり | 増え方 |
|---|---|---|
| `match`（3 文字以上・希少語） | **0.02 ms** | **母数にほぼ依らない** |
| `match`（該当なし） | **0.02 ms** | 同上 |
| trigram 表を `like`（2 文字・希少語） | **1.89 ms** | 母数に比例 |
| 素の `games` を `like`（希少語） | **3.11 ms** | 母数に比例 |
| 素の `games` を `like`（該当なし） | **3.42 ms** | 母数に比例 |

**20,000 行で約 150 倍の差**です。**時間より効くのは `rows_read` です**——本番で
`select id from games where status='published' and title like '%存在しない語句%'` を打つと、
**結果 0 件で `rows_read` が 22**（当時の公開件数）でした。**`like` は結果ではなく母数を読みます。**
**D1 の読み取り枠はアカウント全体で共有で、尽きるとログインも生成も止まります**（5 節の表）。
**いまは `games` が全体で 35 行、うち `status='published'` が 22 行なので、`like` でも何も起きません**
——**効いてくるのは母数が増えてからです。**

#### マイグレーションとしても適用できます

使い捨ての `9999_probe_fts5_370.sql` を置いて `wrangler d1 migrations apply DB --local` を回し、
**`CREATE VIRTUAL TABLE` / `CREATE TRIGGER`（`BEGIN … END;` を含む）/ `INSERT INTO <fts>(<fts>) VALUES ('rebuild')`
のすべてが 1 本のマイグレーションとして通る**ことを確認しました。**トリガ本体の中の `;` で
wrangler の SQL 分割が壊れることはありません。**
**この検証ファイルは削除済みで、`migrations/` は `0026` までのままです。**

- **外部コンテンツ表の同期には、SQLite の仕様上トリガが 3 本要ります**（`CREATE TRIGGER` は
  イベント 1 種類しか扱えないため、insert / update / delete を分けて書きます）。
  ローカルでは 3 本すべてを作り、**insert / update / delete が索引へ伝わること**を確認しました
  （削除した行は `match` に出なくなり、更新した行は新しい題で当たります）。
  **本番では insert / delete の 2 本だけを試しました**（使い捨ての表に対してで、`games` には
  トリガを 1 本も作っていません）。
- 既存行の初期投入は `INSERT INTO games_fts(games_fts) VALUES ('rebuild')` 1 行で済みます。

##### **暗黙の `rowid` に繋ぐのは、#378 で決め直すこと**

**`games` は `id TEXT PRIMARY KEY` なので、`INTEGER PRIMARY KEY` がありません。**
上の検証は `content_rowid='rowid'`（暗黙の rowid）で繋ぎましたが、**SQLite の暗黙の rowid は
`VACUUM` や表の作り直しで変わりえます。** 変わると**索引と本体がずれ、検索結果が静かに壊れます**
——**落ちないので気づけません。**

- **`vacuum` は D1 が拒否しました**（ローカルで実測。`cannot VACUUM from within a transaction`）。

#### #378（キーワード検索）への影響

**設計ごと差し替える必要はありませんが、tokenizer の選択が設計の一部になります。**
**「FTS5 を使う」とだけ決めて着手すると、既定の tokenizer では題を丸ごと打ったときしか当たらず、
キーワードでの部分語検索が 1 件も返りません。**

| 案 | 読み取りコスト | 実装量 | 母数が増えたときの壊れ方 |
|---|---|---|---|
| **A. `trigram` の FTS5 + 2 文字は `like` へ落とす**（推奨） | 3 文字以上は母数に依らない。**2 文字は全走査**（測定で 44 倍差） | 中（マイグレーション 1 本・トリガ 3 本・語長での分岐） | **3 文字以上は平ら。2 文字だけが母数に比例して伸びる**——**逃げ道ではなく、残った穴です** |
| B. `like '%…%'` の全表走査で割り切る | **常に母数に比例**（`rows_read` = 公開件数） | **小**（`where title like ?` だけ） | **急に壊れる。** D1 の読み取り枠はアカウント共通で、尽きると**ログインも生成も止まる** |
| C. 転置索引を自前で持つ（N-gram を表に展開） | 索引が効く。2 文字も引ける | **大**（正規化・同期・再構築を自前で書く。FTS5 が持っているものを作り直す） | 索引表が本体より大きくなる。書き込み枠（**索引の更新も 1 行と数える**）を食う |
| D. 外部の検索サービス | D1 の枠を使わない | **大**（外部依存・秘密・障害時の縮退が増える。9.1「クラウド環境は本番のみ」と相性が悪い） | 運用の面が 1 つ増える |

**A を推します。** **B は「いまは 22 行だから動く」だけで、母数が増えた瞬間に読み取り枠を
直撃します**——**壊れるのが検索だけで済まない**のが B の危険なところです。

**ただし A は「2 文字の日本語」を解いていません。** 2 文字は `like` へ落ちて全走査になるので、
**「`EXPLAIN QUERY PLAN` に全表走査が出ないこと」を #378 の受け入れにそのまま置くと、A は通りません。**
**#378 を起票し直すときに、次の 3 つを決めてください。**

1. **2 文字の日本語で引けること**を受け入れに入れる（入れないと、trigram の穴に気づかないまま
   「日本語で引ける」と判定されます）
2. **2 文字が全走査になることを許すのか**、許すなら**母数の上限**はいくつか。許さないなら
   C（自前の 2-gram 索引）へ寄せる——**ここは A と C の分岐点です**
3. **暗黙の `rowid` に繋がない形**（上の節）

**この 3 つを決めずに着手すると、着手後にまた設計が動きます。**

    衝突しませんでしたが、それは偶然です

  残ります**（直近の 5 件がそうなり、後から手で閉じました）

  レビューも CI も緑のまま通ります——**どちらも「その差分が正しいか」しか見ておらず、
  「その差分がこの PR のものか」は見ていません**
- **`gh pr merge` の衝突は「ブランチが古い」とは限りません。** 上の事故では、**そのブランチの
  内容が別の PR 経由で先に入っていた**ことの現れでした。**そのまま入れると先の 2 本を巻き戻す
  ところで、衝突が唯一の防波堤でした。** 衝突を見たら **`git fetch` してから**
  `git diff origin/main` を取ること（エラー文言から原因を推測しない）。**`origin/main` は
  fetch しないと古いまま**で、確かめたいのはまさに「その間に main が動いたか」なので、
  古い写しを見ると**探している事実だけが見えません**

### 実物を通すまで、動いているかは分からない

**「プレイ経路は本番で動作」と 2 日にわたって報告していたが、実際には動いていなかった**（#180 / #181）。
根拠にしていたのは **`curl` の 200 と CSP の文字列照合**で、**どちらも CORS を評価しない。**

| 検査 | 通してしまうもの |
|---|---|
| CSP の文字列照合・`curl` | **CORS**（評価しない） |
| `SELF.fetch`（vitest の workers pool） | **HTTP のエンコード**（境界を通らない） |

**どちらも「緑だから正しい」と読める形だった。** 実ブラウザを通して初めて見え、しかも
**1 つ目を直した時点で止めていれば 2 つ目を本番でもう一度踏んでいた**（ブラウザ検査の層が
赤のまま残ったことが、それを防いだ唯一の理由）。

**配信を触ったら `scripts/check-sandbox-browser.sh` を回すこと。** 層 0 は**ブラウザ不要**で
30 秒（`GF_SKIP_BROWSER=1`）、しかも**いちばん見えにくい二重圧縮をそこで捕まえる。**

**そして、同じ根で両方向に間違えた。** 「`Accept-Encoding` の有無でサイズが違う」のを
「Cloudflare の再圧縮だろう」と流して二重圧縮を見逃し、直したあとは正しい本文を
「二重圧縮だ」と誤報した。**どちらも「経路が透過的に展開しうる」ことを勘定に入れていない。**

### 変異が当たったことを、変異の結果より先に確かめる

**第 5 波で、こちらが 3 回続けて「緑だから空振りだ」と誤読しかけた。** `sed` の綴りが
本文の整形変更で当たっておらず、**ファイルは変わっていないのに変異したつもりでいた**
（1 回はコメント行だけを書き換えていた）。**md5 か `grep` で当たったことを確かめてから
回すこと。** 当てていない変異の緑は、検査の欠陥ではなく手順の欠陥である。

**同じことを書いた本人が自分で踏んだ例もある。** #26 で足した「既定値が戻っていないこと」の
検査は、設定の読み取りを別ファイルへ移した瞬間に**何も見なくなった**（`process.env[...] ??`
という綴りを探していた）。**綴りを絞った検査は、対象の綴りが変わった日に黙って空振りする。**

### 変異が当たっても、変異が弱いと緑になる

**上の「当たったことを先に確かめる」だけでは足りません。** 波 1 の取り込みで、4.5 の
キャッシュ検査へ揮発値として `Date.now()` を混ぜる変異を当てました。**`md5` は変わって
いたのに、テストは緑でした。** 2 回の呼び出しが同じミリ秒に入っただけで、`Math.random()`
に替えると赤になりました。

**当てたことの確認と、変異の強さは別の話です。** 当たった変異の緑は、検査の欠陥とも
手順の欠陥とも読めます。**その変異が「確かめたい性質」を本当に壊しているかまで見ること。**

### 確認に使う `grep` そのものを疑うこと

**`grep` の引数は正規表現として解釈されます。** 波 1 の取り込みで
`grep -c 'builds/${sourceSha256}'` が **0 件**を返し、これを「復元できていない」と
読みかけました（テストが緑だったので矛盾に気づけました）。

**原因は `$` です。行末アンカーとして解釈されるため、`$` の後ろに文字が続く綴りは
決して当たりません。**

```
$ printf 'a$b\n' > /tmp/t
$ grep -c 'a$b'  /tmp/t   # → 0（$ が行末アンカー）
$ grep -c 'a\$b' /tmp/t   # → 1（エスケープすれば当たる）
```

**`{}` のせいだと 1 度書きましたが、違いました**（レビューで指摘され、実測して直しました。
`{}` はこの綴りでは効いていません）。**思い込んだ原因を書くと、次の人が別の綴りで同じ罠に
落ちます。**

- **変異や復元の確認には `grep -F` を使うこと**（固定文字列。`$` も `{}` も素通りします）
- **この環境の `grep` は ugrep です**（`grep --version`）。**利用者の端末（macOS）は
  BSD grep で、また別です。** スクリプトへ書く `grep` も `-F` を明示するほうが安全です
  （#210 のレビューで同じ指摘が出ました）

### 検査そのものを疑うこと

**緑の検査が何も確かめていないことがあります。** #160 で停止対象を IAM ユーザーからロールへ
移したとき、層 3 の検査は識別子を取れずに**赤**になりましたが、層 2 の検査は**消えた output（空）と
消えた環境変数（空）を突き合わせ、空どうしが一致して緑**でした。**確かめていない検査は、
確かめた証拠として読まれるぶん赤より悪い。**

**移動は 3 点セット（許可・停止・検査）です。** 検査の追随漏れは
`scripts/check-tf-output-refs.sh` が機械で見ます。
