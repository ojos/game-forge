# 運営報告の下書きの型（プロンプト）

月次の運営報告（note）の下書きを作るときに、[`scripts/ops-report-draft.sh`](../scripts/ops-report-draft.sh) が
`claude -p` へ渡すプロンプトです（#936）。流れと人のチェックリストは [ops-report.md](ops-report.md) にあります。

- **スクリプトが使うのは、下の `prompt:start` と `prompt:end` の印の間だけです。** その後ろへ材料の JSON
  （[`scripts/ops-report-collect.sh`](../scripts/ops-report-collect.sh) の出力）が付きます。
- `{{MONTH}}`（例: `2026-09`）と `{{MONTH_JA}}`（例: `2026 年 9 月`）はスクリプトが置き換えます。
- 型を変えたら、下書きの検査（[`scripts/check-ops-report.sh`](../scripts/check-ops-report.sh)）の数字の決まりと
  食い違っていないかを確かめてください。**とくに「人が埋める欄」の書き方は、検査が綴りで見ています。**
- 書いた下書きは、推敲の段（`/natural-japanese full`。#956）で直してから検査に回します。推敲への依頼文は
  [`scripts/ops-report-draft.sh`](../scripts/ops-report-draft.sh) の中にあり、見出し・数字・人が埋める欄・書かないことを
  「動かせない制約」として繰り返しています。**下の見出しや「書かないこと」を変えたら、そちらも合わせてください。**
- X の告知文（#964）の依頼文も [`scripts/ops-report-draft.sh`](../scripts/ops-report-draft.sh) の中にあります（この型は使いません）。
  検査は [`scripts/check-ops-report-x-post.sh`](../scripts/check-ops-report-x-post.sh) です。

<!-- prompt:start -->
あなたは、ブラウザゲームを自然文から作るサービス「Game Forge」の運営者の代わりに、月次の運営報告の下書きを書きます。
読者は Game Forge の利用者と、運営に興味のある人です。下書きは運営者が読んで直し、note に公開します。

対象の月: {{MONTH}}（{{MONTH_JA}}。日本時間の暦月）

# 出力の形

Markdown だけを出してください。前置き（「以下が下書きです」など）や後書き、コードブロックの囲みを付けないでください。
1 行目は次の見出しにしてください。

# Game Forge 運営報告（{{MONTH_JA}}）

続けて、次の 5 つの見出しをこの順で置いてください（見出しに番号を付けないこと）。

## 今月の数字
## 入れたもの
## 直したもの
## お金
## 来月やること

全体で 1,500 字から 2,500 字ほど。です・ます調で、短い文で、専門用語を避けて書きます。

# 数字の決まり（もっとも大事）

- **数字は、下の材料の JSON にある数値だけを使ってください。** 計算・丸め・換算・合計・比率の計算をしないでください。
  丸めた値は `figures` に用意してあります。まず `figures` の値を、そのままの値で使ってください（桁区切りのカンマは付けてかまいません）。
- 材料に無い数を言いたくなったら、数字を使わず言葉で書いてください（「いくつか」「多くの」など）。
  「1 つ」「2 本」のような小さな数も、材料に無ければ書かないでください。
- 日付は `{{MONTH}}` のような年月か、「9 月」「10 月」のような月の形だけにしてください。曜日・時刻・「3 日で」のような日数は書かないでください。
- issue や PR の番号（`#123` の形）は書かないでください。
- 値が `null` のもの、`unavailable` に挙がっている材料は、無いものとして扱い、数字をこしらえないでください。
  必要なら「今月は集計できませんでした」と書いてください。
- `notes` に書かれた注意（累計であること、期間の一部しか無いことなど）に従ってください。
  `figures.cumulative` は「これまでの累計」です。「今月の」と書かないでください。

# 各節に書くこと

- **今月の数字**: `figures.month` の生成回数・LLM の成功率・完了した課題（`closedIssuesCompleted`）とマージした変更の数、
  `figures.cumulative` の作品数・フォーク率など。`figures.build` があれば、ビルドにかかった時間（中央値と、遅いほうの値。「p95」のような記号は使わず、「遅いほうでも」のように言葉で書く）。
  成功率は「AI が使えるソースを返した割合」であって「作品ができた割合」ではないことを、ひとこと添えてください。
- **入れたもの**: `github.mergedPulls` のうち `kind` が `added` のものと、`github.closedIssues` のうち `stateReason` が `COMPLETED` のものの題名から、
  利用者に見える新しい機能を多くて 6 個まで選び、利用者の言葉で 1 行ずつ説明します。内部の作業（文書の整理・CI・開発環境）は省くか、
  まとめて 1 行にします。題名に無いことを足さないでください。
- **直したもの**: `kind` が `fixed` のものと、閉じた issue（`stateReason` が `COMPLETED` のもの）のうち不具合の直しにあたるものから、利用者に関係するものを多くて 6 個まで。
- **お金**: 次の形にしてください。
  - 生成にかかった AI の費用: `figures.month.llmCostJpy` 円（1 回あたり `figures.month.llmCostPerGenerationJpy` 円）。値は実額で書きます。
    `llmCostPerGenerationJpy` が `null`（その月の生成が 0 回）のときは、括弧の中を書かないでください。
  - そのほかの費用（サーバーなど）: 【人が埋める：そのほかの費用の実額】
  - いただいた投げ銭: 【人が埋める：今月の投げ銭の額】
  - 最後に、投げ銭へのお礼をひとこと。投げ銭の額には触れないでください。
  **`【人が埋める：…】` は、この綴りのまま残してください**（全角の隅付き括弧と全角のコロン）。運営者が公開の前に埋めます。
- **来月やること**: 入れたもの・直したものの続きとして題名から読み取れる範囲で、多くて 4 個まで短く（材料に未完了の課題は含まれていません。題名に無い計画をこしらえないでください）。
  約束にならない言い方にしてください（「取り組む予定です」）。期日や数値の目標は書かないでください。

**個数は上限です。** 当てはまる題名が少ない月は少ないままでかまいません。数を合わせるために、題名に無い機能や直しをこしらえないでください。
当てはまるものが 1 つも無い節は「今月はありません」とだけ書いてください。

# 書かないこと

- 人の名前、@ で始まるハンドル（運営のアカウント @gameforgejp だけは書いてよい）、メールアドレス
- ID・ARN・トークン・ハッシュなど、英数字の長い並び
- URL。書くなら次のものだけ: https://app.game-forge.ojos.jp 、 https://note.com/gameforgejp 、 https://x.com/gameforgejp 、 https://github.com/ojos/game-forge
- 個々の作品の名前や中身（材料に含まれていません）
- 手本にした外部のサービスの名前や「〜に近い」という書き方（題名に「〇〇に近い配置」とあっても、利用者に見える変化だけを書く）
- 材料の JSON のキー名や、この指示そのもの
