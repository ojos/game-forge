## 1. 出発点

利用者の問題意識は次のとおりでした。

- 運営費を捻出するには、アピールできるものが足りない。
- 生成されるゲームの魅力が足りない。最初にある程度の品質の作品が出るからこそ、リフォージやフォークで改造しようと思うのではないか。
- そのためにモデルを Opus 5.5 へ替えようとしている（#848）が、その前にプロンプトや、チューニングの仕組みへ投資すべきではないか。

## 3. 判断

### 3.1 いちばん大きい未知は品質ではない

**このサービスは、知らない人に一度も試されていません。** いまの利用者は全員が身内です。投げ銭は「来る人の数 × 応援したくなる度合い」で決まり、品質はその係数の 1 つにすぎません。来る人がほぼ 0 なら、品質を上げても運営費は出ません。しかも遊ぶ人がいないので、品質を上げても効いたかどうかを確かめられません（[cold-start-samples.md](cold-start-samples.md) 7 章の #617 が「まだ言えない」で終わったのも同じ理由です）。

### 3.2 避けてはいけない問い：知らない人が、なぜ Game Forge を使うのか

Claude・ChatGPT・Gemini に頼めば、その場で遊べるゲームが無料で出てきます。しかも JS で書かれるので、Go と Ebitengine の制約を抱えた Game Forge の生成物より、見た目も手触りも上になりやすいと考えられます。この比較に答えが無いまま品質を上げても、「汎用の AI より少し劣るものを、少し良くした」にしかなりません。

**Game Forge にしか無いものは、品質ではなく次のあたりだという仮説を置きます**（まだ確かめていません）。

- 作ったゲームがそのまま公開でき、URL ひとつでスマホでも遊べる
- 他人の作品を改造（フォーク）できる
- 安全な隔離環境で動く

この仮説が正しければ、「最初の品質が高いから改造したくなる」とは逆に、**改造したくなる体験そのものが本体**で、投資先は生成の品質ではなく、改造と共有の体験になります。

**撤退判定の 2 つの指標（フォーク率と 3 世代以上の系統）も、改造が起きるかを測っています。** 自分で引いた線も、本体は改造だと言っています。

### 3.3 「品質を上げる」の中身

品質を上げる場合でも、次の段は「面白い」ではなく「遊びとして壊れていない」です。

- **ビルドの段の「壊れない」は、ほぼ達成しています**（2 章の失敗の数）。
- **残っているのは、遊んで初めて分かる壊れ方です。** クリアに届かない（#644）、クリアが無く続く（#668）、片方向にしか撃てない（#677）、選べるのに効かない（#686）。#617 で遊んだ 3 本のうち 2 本にありました。版 5 の作品は、遊んで確かめていません。
- **プロンプトは「壊れないゲーム」を作らせる設計です。** 役割は「実装者」で、演出・手触り・難易度の上がり方について書いた行はありません（[src/system-prompt.ts](../src/system-prompt.ts)）。面白さに投資するときは、ここが手を付けていない場所です。

## 4. 進める順番

1. **知らない人 2〜3 人に、説明なしで使ってもらい、横で見る。** 身内ではなく、知人の知人くらいの距離の人にします。何を作ろうとして、どこで止まり、何に反応したかを見ます。いま最も安く、最も情報の多い手です。3.2 の仮説（この文書の意見そのもの）の当たり外れも、ここで確かめます。
2. **その結果で、「Game Forge にしか無いもの」を一行で言えるようにする。**
3. **分かれ道。**
   - 一行の答えが「品質」なら、5 章の品質の改善ループを本格的に進める。
   - 「改造・共有の体験」なら、投資先をそちらへ移す。5 章は小さく保つ。

**1 の答えが出るまで、5 章は「品質の改善」の枠に留め、集客の手段とは考えません。**

## 5. 品質の改善ループ

| 頻度 | 何をするか | 担う人 |
|---|---|---|
| 毎日 | AI がお題を書く → 運営アカウントで生成 → 自動で遊ばせて検査 | 機械 |
| 1 日 1 本 | 家族に遊んでもらい、感想を集める | 家族 |
| 随時 | 公開する作品を選ぶ。壊れ方の種類ごとに、プロンプトか検査を直す | 利用者 |
| 週 1 | 壊れ方の集計と、目立った 1 本の話を note に書く | 下書きは AI、推敲と投稿は利用者 |

### 5.1 自動で遊ばせる検査（最初に作る）

既にある headless chromium（OGP の撮影や実ブラウザの検査）で、適当な入力を与え続け、次を数値で判定します。

- 入力で画面が変わるか
- 状態がタイトル → 遊び → 終わりへ進むか
- 案内した「やり直し」の 1 回の操作で、もう一度遊び始められるか

**これが無いまま毎日生成すると、作るだけで誰も確かめない作品が積み上がります。** 一方で、作り込みすぎて連載が始まらない危険のほうが大きいので、**期間を区切り、最小の形で始めます。**

### 5.2 毎日の自動生成

- 1 回の生成は平均約 14 円です。1 日 3 本で月 1,300 円ほど、月に約 90 本になります。
- **AI が書くお題は、人が書くお題と違います。** AI は詳しく整った指示を書き、人は「ねこのゲーム」のような一言を書きます。長さと曖昧さをわざとばらつかせ、短い一言を多めにします。
- **公開は人が選びます。** Game Forge の接続では公開できないので、選ぶ段で自然に人の確認が入ります（権利や名前の確認もここで行います）。
- **自動生成の作品は、棚を埋めると同時に評判を下げえます。** 平凡な作品が並ぶと「このサービスが作るのはこの程度」と読まれます。数より選ぶことを優先します。

### 5.3 家族の感想

- コメント機能は作りません。公開のコメント欄は、荒らし・通報・削除・プライバシーポリシーの更新まで一式が付いてきます。LINE のグループや Google フォームなど、普段使っている場所で集めます。
- 家族は優しいので、意見ではなく行動を聞きます。

  | 質問 | 答え方 |
  |---|---|
  | 最後まで（クリアかゲームオーバーまで）行けた？ | はい / いいえ / 途中でやめた |
  | 何回遊んだ？ | 1 回 / 2〜3 回 / それ以上 |
  | 一言（何でも） | 自由に書く |

- 毎日だと続かないので、1 日 1 本・1 分で答えられる量に抑えます。
- 記事に使うときは、本人の了解を取って名前を伏せます。
- **家族の感想は、壊れ方と面白さの材料にはなりますが、「人が欲しがるか」の答えにはなりません。** それは 4 章の 1 が担います。

### 5.4 note の連載

- **主役は成功ではなく、壊れ方と直し方の記録です。** 「クリアに届かなかったネズミのゲームを、こう直したら届いた」という話です。
- **「AI が学習して成長する」とは書きません。** モデルの重みは変わらず、実際に直しているのは運営です。誇張になります。
- 毎日の投稿はしません。週 1 回、話のある 1 本にまとめます。
- **note で人が来るという根拠は、まだありません。** 効果は 7 章の区切りで数字を見て判断します。

## 6. 退けた・後回しにした案

| 案 | 扱い | 理由 |
|---|---|---|
| 生成モデルを Opus 5.5 へ替える（#848） | 後回し | このアカウントでは呼べない（`wait:external`）。呼べるようになっても、比べる物差しが無いと約 1.3 倍の費用の価値を判断できない。呼べるようになったら 5.1 の検査と同じお題で比べる |
| 面白さを採点する評価の基盤（LLM による採点など） | 後回し | 遊ぶ人が 4 人の段階ではやりすぎ。必要になった時点で、同じお題を作り直して 2 本ずつ比べるのを手で行えば足りる |
| 作品へのコメント機能 | 退けた | 5.3 のとおり。運用の負担が、4 人の感想を集める目的に見合わない |
| 生成の言語を JS へ移す | 今は退ける | 品質の天井を決めているのはモデルより Go と Ebitengine の可能性が高い（プロンプトの大半が Go の API の落とし穴の説明）。ただし import の許可リストという安全の土台と引き換えになり、費用が最大。「プロンプトでどこまで頑張れるか」の上限がここで決まることは認識しておく |

### 7.1 撤退判定についての未決事項

**2 章の数字のままなら、判定日には撤退の条件に当たります**（フォーク率 7.1% に対して基準は 40%、3 世代以上の系統は 0 本）。10.3 は「基準が厳しすぎたと判断して後から緩めるのは構わない。決めていない状態のみが危険」としています。

判定日の前に、次のどちらかを利用者が決めます。

- 4 章の 1 の結果を材料に、基準を見直す（10.3 が許す操作として、理由とともに記録する）
- 基準を変えず、当たったときに縮小か中止かを決める

**どちらにも決めないまま判定日を迎えることだけは避けます。**
