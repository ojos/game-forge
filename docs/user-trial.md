# 知らない人の試用キット

**知らない人に Game Forge を一人で試してもらい、その様子と答えをサイトの中で受け取るための手順一式です**（#972。2026-10-11 にサイトの中で完結させる形へ組み直した。#977・#978）。

- 位置づけ: [strategy.md](strategy.md) 4 章の 1 を実行するための手順。なぜ試用するのか、結果で何を決めるのかは strategy.md にあり、ここへは書き写しません。
- 対象: 職場や友人のうち、仕様 2.1 のペルソナ（ネットミーム好き・大喜利好きの 20〜40 代）に近い人を 3 人。家族と開発者は外します。AI でゲームを作った経験がある人と無い人を混ぜます。
- 形: 試用者は **PC** のブラウザで `/trial` を開き、同意 → 録画 → 自由に触る → 声で振り返り → 短い文字のアンケート、をサイトの中で終えます。運営は横にいません。**スマホは対象外です**（スマホのブラウザは画面を取り込めない。この限界は strategy.md 4 章に書いた）。

**リポジトリは public です。** 録画・文字起こし・観察シート・行動の記録・試用者の名前やハンドルは、リポジトリに入れません。試用の控えは、リポジトリの外（Mac の手元など）に 1 人 1 フォルダで置きます。リポジトリに残してよいのは、名前を伏せた 8 章のまとめだけです。

---

## 1. 準備

| 何を | どうする |
|---|---|
| 招待コード | 運営アカウント（@gameforgejp）で `/invites` から 1 人 1 つ発行します。**運営アカウントから招待すると、登録した人の「誰の招待か」が運営になり、試用者を家族と分けて数えられます。** 3 つは 2026-10-11 に発行済みです |
| 試用者の印 | 試用者が招待コードで登録し、ハンドルを決めた後に、4 章の SQL で印を付けます。**印の無い人には `/trial` が 404 になります** |
| 控えのフォルダ | リポジトリの外に、試用者ごとのフォルダを作ります（例: `~/game-forge-trial/p1/`）。名前ではなく `p1`〜`p3` の番号で呼びます |
| 録画 | #978 が入るまで、試用は始めません（2026-10-11 の決定）。録画は `/trial` の中でブラウザが取り、非公開の保存場所へ送られます |

## 2. 試用者へ送る文面

**説明・同意・質問は、すべて `/trial` のページに出ます。** 送るのは、登録の案内と `/trial` への入り口だけです。**フォークのことは言いません**（誰にも言われずにフォークを見つけて押すかどうかが、いちばん知りたいことの 1 つ。strategy.md 3.2）。

> 自分で作っている「Game Forge」というサイトを、試しに使ってみてもらえませんか。20〜30 分くらいです。
>
> 1. 下の招待コードで登録してください（Google のアカウントでログインします）。登録できたら、一言教えてください。
> 2. こちらで準備ができたら連絡するので、**PC のブラウザ**（Chrome・Edge・Safari・Firefox のどれか）で https://app.game-forge.ojos.jp/trial を開いてください。あとはページの案内どおりに進めてもらえれば大丈夫です。
> 3. マイクを使うので、声を出せる場所でお願いします。
>
> 招待コード: （ここにコード）

## 3. `/trial` の流れと文面

**ページの文面（説明・同意・振り返りの 5 問）の正本は [src/trial-text.ts](../src/trial-text.ts) です。** ここへは写しません——写すと、機械で照合しない限り片方が古くなります（shared-ai-rules 12 章）。文面を変えるときはそのファイルを直し、**同意の意味を変えたら `TRIAL_CONSENT_VERSION` を上げます**（誰がどの文面に同意したかを後から突き合わせるため）。

| 段 | 試用者がすること | 記録すること（`trial_participants`） |
|---|---|---|
| 説明と同意 | 説明を読み、「同意して始める」を押す。同意しなければ閉じるだけ | 同意した時刻と同意の文面の版。**同意の前は何も書かない** |
| 録画の準備 | 録画を始める（#978。録る画面とマイクを選ぶ） | （#978 が録画の開始時刻を記録する） |
| 自由に触る | Game Forge を別のタブで開き、自由に触る。終わったら「触り終えた」 | この段に入った時刻 |
| 振り返り | 5 問が 1 問ずつ出るので、**声で**答える | 各問を出した時刻（録画と突き合わせて、答えの区間を切り出す） |
| アンケート | 録画を止め、ブラウザ・AI の経験・言い損ねたことを文字で答える | 答えと、終えた時刻 |

**5 問を声で答えてもらうのは、正直な反応を取るためです。** 文字にすると考えてから書くので、知り合いへの気遣いが入りやすくなります（2026-10-11 の決定）。文字のアンケートは、録画からは確実に読み取れないものと、言い損ねたことの補足だけを受け持ちます。

## 4. 印を付ける・記録を消す

本番の D1 への書き込みです。**値（ハンドル）は実行のときに読み、事前に埋めた id を使いません。**

```bash
# 印を付ける（試用者のいまのハンドルから）
npx wrangler d1 execute DB --remote --env production --command \
  "insert into trial_participants (user_id, marked_at)
   select user_id, unixepoch() from handles where handle = '<ハンドル>' and released_at is null"

# 試用者に頼まれたら、すぐ消す（印ごと消える）。<利用者の id> は /trials の各行に出る id を、その場で写す
npx wrangler d1 execute DB --remote --env production --command \
  "delete from trial_participants where user_id = '<利用者の id>'"
```

**消すときはハンドルではなく、`/trials` に出る利用者の id で指定します。** 退会や改名でハンドルを手放した人は、ハンドルからは引けず、0 件のまま成功してしまうためです。実行した後、出力の `changes` が 1 であること、`/trials` からその行が消えたことを確かめます。

- **頼まれなくても、同意した日から 90 日で消えます**（後片付けの cron。[cleanup-worker.md](cleanup-worker.md)）。
- 消すように頼まれたら、上の SQL に加えて、録画（#978 の非公開の保存場所）と、そこから作った文字起こし・静止画・観察シート（控えのフォルダ）も消します。
- 退会しても、試用の記録はそれだけでは消えません（90 日で消える。`/privacy` にもそう書いた）。

## 5. 結果を読む

| 何を | どこで |
|---|---|
| 段の時刻・同意・アンケートの答え | 管理画面（admin ホスト）の `/trials` |
| 録画 | #978 の管理画面からの取り出し |
| 生成のお題・作品・フォーク・公開 | 下の `scripts/trial-timeline.sh` |
| 文字起こし・静止画・観察シートの下書き | #974 の分析のスクリプト |

録画では、生成のお題の文面が画面の端に小さく出るだけです。台帳から時刻つきで取り出し、録画と突き合わせます。

```bash
bash scripts/trial-timeline.sh --remote --handle <試用者のハンドル> > ~/game-forge-trial/p1/timeline.txt
```

- 出るのは、登録・生成とチャットの呼び出し（お題の文面つき）・作品の作成とフォーク・公開・版の 5 種類です。時刻は JST です。
- **いいねとプレイは出ません。** どちらも台帳には作品ごとの数しか無いためです（詳しくは [scripts/trial-timeline.sh](../scripts/trial-timeline.sh) の冒頭）。録画で見ます。
- **出力には試用者のお題の文面が載るので、リポジトリの外へ保存します。** 上の例のように、控えのフォルダへ書き出します。
- `--format json` で、分析の段（#974）へ渡す形でも出せます。

観察シートの下書きは、管理画面から落とした録画と、上の `--format json` の出力から作れます（#974）。音声は手元で文字起こしし、Claude へ渡すのは文字起こし・静止画・操作の種類と時刻だけです（お題の文面は渡しません）。

```bash
bash scripts/trial-analyze.sh <録画> --out ~/game-forge-trial/p1/analysis --participant p1 --timeline ~/game-forge-trial/p1/timeline.json
```

## 6. 観察シート

録画を見ながら、1 人に 1 枚埋めます（控えのフォルダに置きます）。分析の段（#974）が下書きを作る場合も、この項目に沿います。

| 項目 | 記入の仕方 |
|---|---|
| 試用者 | `p1` などの番号。ブラウザと、AI でものを作った経験の有無（`/trials` のアンケートから写す） |
| 同意 | `/trials` の同意の時刻と版 |
| 最初の 1 分 | 最初に何を見て、何を押したか |
| 作ろうとしたもの | お題の文面（5 章の行動の記録から写す）と、その意図を話していればその発言 |
| 止まった所 | 時刻・画面・何に迷ったか（発言を引く） |
| 反応 | 笑った・驚いた・がっかりした瞬間。時刻と、何に対してか |
| 他人の作品 | 開いたか。何本か。遊んだか |
| フォーク | **誰にも言われずに押したか**。押したなら、何を変えようとしたか |
| 共有 | URL のコピー、スクリーンショット、「見せたい」という発言があったか |
| もう一度 | 同じ作品を 2 回以上遊んだか。作り直したか |
| 質問への答え | 5 問それぞれ（要約と、印象的な発言をそのまま）。`/trials` の各問の時刻で録画の区間を探す。アンケートの「言い損ねたこと」も併せる |
| 不満 3 つ | 3 問目の答えをそのまま |
| 運営の気づき | 見ていて思ったこと。仮説につながりそうなこと |

## 7. 「お金を払いますか」は聞かない

5 問に、支払いの意思を聞く問いは入れていません。仮定の質問への答えは、実際の行動と一致しないからです。5 問は、意見ではなく事実と行動を聞く形にしてあります（[src/trial-text.ts](../src/trial-text.ts) の `TRIAL_QUESTIONS`）。

## 8. まとめの型

3 人の観察シートがそろったら、strategy.md の 3 つの仮説に一行ずつ答えます。**ここだけは名前を伏せたうえで、strategy.md に残してよいものです。**

| 仮説 | 一行の答え | 根拠（観察シートの番号と項目） |
|---|---|---|
| 改造したくなる体験こそが本体か（誰にも言われずにフォークしたか、他人の作品を開いたか） | | |
| 汎用の AI（ChatGPT など）より優れている点はあるか | | |
| 生成の品質が、使い続けることの障害になっているか | | |

そのうえで、strategy.md 4 章の 2「Game Forge にしか無いものを一行で」を書きます。3 人では結論を出せないこともあります。そのときは「分からなかった」と書き、何が分からなかったかを残します。それも 4 章の 3 の分かれ道の材料になります。**PC で試した結果であることも、一緒に書きます。**
