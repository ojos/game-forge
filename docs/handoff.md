## 1. 現在地

**生成は本番で動いており、利用者は送信したらタブを閉じてよくなりました。**

```
/generate → クォータ判定 → games 行を作る → 202 と URL を返す（約 0.5 秒）
                                      ↓ 非同期
        [オーケストレータ Lambda] 生成 → 台帳 → import 検査 → ビルド関数 → R2
                                      ↓ コールバック
                              games 行を完成（preview_key が入る）
```

**実測（2026-08-30）: 送信から完成まで 107 秒、1 回 18.49 円。** 利用者は待ちません。

- **接続を切っても完走することを本番で確認済み**（タブを閉じ、あとから `/works/<id>` を開き直した）
- **プレイ経路も本番で動いています。** ただし**ここへ来るまでに 2 つの不具合を踏みました**（#180 / #181）。
  経緯は 4 章「実物を通すまで、動いているかは分からない」を読んでください
- **メールも届きます**（#178。DKIM / SPF / DMARC はすべて `game-forge.ojos.jp` のゾーン内で完結。
  `ojos.jp` には 1 本も置いていません）
- 実行体の設計と経緯は仕様 1.2.39 と [orchestrator.md](orchestrator.md) にあります

### 公開できるようになりました（#26 / #30 / M4）

**`draft → published` の経路が入り、`/g/<game_id>/` が使えるようになりました。** 作品ページ
（`/works/<game_id>`）の「公開して共有」を押すと状態が変わり、**公開時に OGP を 1 枚撮ります**
（AWS Lambda の headless chromium。`terraform/ogp-function.tf` / `docker/ogp-shot/`）。
作品ページはロード中の数秒に**スクリーンショット・作者名・元ゲーム・「このゲームを改造する」**を
先に出します（#30）。

**ただし、本番では 1 枚も撮っていません。** イメージの push も `terraform apply` も
**まだです**（下の 2 章）。**「実物を通すまで、動いているかは分からない」**（4 章）。
最初の公開でまず疑うのは次の 3 つです。

| 疑うもの | 症状 |
|---|---|
| `@sparticuz/chromium` / `puppeteer-core` の版 | イメージのビルドが解決できない |
| Lambda 上の WebGL（swiftshader） | 画像が真っ黒／真っ白 |
| 合図後 1,500 ms（見積もりで実測ではない） | 「読み込み中」の文字が写る |

**撮り直しの経路はありません。** 関数ごと落ちると `ogp_state='capturing'` のまま残ります（#26 の未実装）。

**次は M5（フォーク連鎖＝コア仮説）です。** #30 で「改造する」の**未ログイン側**の導線が
`/signup?from=fork-cta` として通り、**10.2 のフォーク率の分子に初めて送り手ができました**
（受け皿だけあって 0 のままでした）。**ログイン済み側は生成画面へ送っており、M5-1 が入ったら
フォークの入口へ差し替えます。**

**M4 は閉じていません。** #191〜#193（推敲まわり）が新しく起票されており、これらは今回の対象外です。

`ojos.jp` そのものなら別ゾーン（さくらから委譲）で**人が入れます**。
**手で足すと外部層の「terraform plan: no drift」が赤くなります。**

### ★ 適用していない宣言が 3 つあります（利用者の端末で叩く）

**コードは main に入っているのに、外部状態が追いついていません。** この状態のまま外部層を
回すと赤が出ますが、**それは実装の誤りではありません。**

| やること | 何が起きるか（やらないと） |
|---|---|
| `npx wrangler d1 migrations apply DB --remote --env production`（**0009 / 0010**） | **どちらも落ちない壊れ方をします。** 公開後の撮影が `no such column` でログにだけ出て、degrade の信号は永久に立たない（黙って #24 の近似に戻る） |
| ECR へ OGP 撮影イメージを push（**先に `terraform apply -target=aws_ecr_repository.ogp_shot`**。空だと関数の作成が落ちる） | OGP が 1 枚も撮れない。手順は `docs/ogp-capture.md` 3 章 |
| `terraform apply` | オーケストレータの `timeout` が 600 のまま（宣言は 840。#174）。外部層が `Timeout` の乖離で赤 |

**0002〜0005 を忘れて 16.75 円を捨てた前例があるので、D1 の 2 本を最初に打つのが安全です。**

## 3. 触るときの注意

- **生成経路は課金されます。** 1 回 **約 16〜19 円**（実測 15.80 / 16.75 / 18.49 円）。サブエージェントには「`/api/generate` を
  実際に呼ばない」と明示すること。テストは経路層のハンドラを直接叩きます
- **本番 D1 のマイグレーションは手作業です。** デプロイでは走りません。**スキーマに触る PR を
  入れたら `npx wrangler d1 migrations apply DB --remote --env production` を忘れないこと**
  （0002〜0005 を忘れて 16.75 円を捨てた前例があります）
- **実行環境は本番への書き込みを止めます。** 読み取り（SELECT・CloudWatch・terraform plan）は
  通りますが、`migrations apply` / `terraform apply` / R2 への書き込みは**利用者の端末**で叩きます
- **エッジの長命 AWS 鍵は `BUILD_AWS_*` の 1 組だけ**になりました（#160）。できるのは
  「オーケストレータへジョブを 1 回投げる」ことだけです。**`BEDROCK_AWS_*` は削除済み**
- **利用者の端末は macOS です。** スクリプトに GNU 拡張（テンプレート無しの `mktemp`、
  `date +%N`、`sha256sum`、GNU sed の `\x`）を書かないこと。`scripts/check-shell-portability.sh`
  が表にある綴りを落としますが、**網羅ではありません**（表は踏んだ事故を足していく形）
- **worktree で `npm run types` を打つ必要は無くなりました**（#175）。生成物が `wrangler.toml`
  より古いと、`npm run typecheck` / `npm test` の**手前**で `scripts/check-worker-types-fresh.sh`
  が 20ms で落とし、`npm run types` と出します。**直しはしません**（判定と修復は混ぜない）
- **開発環境の Go はピン留めと揃えません**（#185。確定12）。go が `go.mod` を読んで自分で
  切り替えるので、**`go env` はモジュールの中で引くこと。** 外で引くと切り替え前の版を見ます
  （#180 の `wasm_exec.js` と同じ取り違え）。**開発環境で `GOTOOLCHAIN=local` を設定しないこと**
- **`mapfile`（bash 4+）依存が残っています。** macOS の `/bin/bash` は 3.2 です。利用者が
  自分の端末で外部層を回すと落ちます。未対応
- **AWS SSO と GCP の ADC は切れます。**
  `aws sso login --profile game-forge-prod --use-device-code` /
  `gcloud auth application-default login --no-launch-browser`。**GCP は認証後に
  `ido@ojos.jp` であることを必ず確認**（別アカウントでも成功し、`terraform plan` が
  権限エラーになるまで気づけません）
- **terraform を叩くときは `CLOUDFLARE_API_TOKEN` を載せること**（`set -a; . scripts/load-project-env.sh; set +a`）。
  載せ忘れると R2 のリソースの読み戻しが 9106 で落ち、**プロバイダの不具合に見えます**
- **仕様の古い記述は削らず、注記を足して残します**
- **マージは squash のみ。利用者の明示的な指示があるまでマージしません**

## 4. 並列作業のやり方

worktree とサブエージェントで **計 7 波・18 レーン**を走らせました（3 レーン × 4 波 →
**3 / 2 / 1 レーンの 3 波**）。**第 2 波以降、レーンどうしの所有ファイルの衝突はゼロです。**

**波の大きさは issue の数ではなく依存で決めます。** 直近の 3 波は「バグ 3 件を並列 →
機能 2 件 → その 2 件に依存する 1 件」で、**後ろの波ほど細くなりました。**

- **所有ファイルを重ねない。** レーンごとに明示して渡す
  - **重ねるのはレーンではなく、渡す側です。** 直近の波で `test/schema.test.ts` を 2 レーンの
    所有に書いてしまいました（どちらもマイグレーションを足したため）。**渡す前に、レーンの
    所有一覧どうしを機械で突き合わせること**（`comm -12`）。今回は触った行域が離れていて
    衝突しませんでしたが、それは偶然です
- **`docs/product-spec.md` は誰にも編集させない。** 各レーンは文面を報告に書いて返し、
  **取り込む側が版と節番号を付けて 1 本のブランチで入れる。** これで衝突が消えました
- **マイグレーションの連番は先に割り当てる**
- **1 つの継ぎ目を触る 2 issue は同じレーンに畳む**（#28/#29、#148/#153、#164/#165、#149/#166）。
  1 issue = 1 PR は守りつつ、worktree は 1 つにして直列に出させる
- **worktree を消さない。** 再利用すると `node_modules` が残り `npm ci` を省けます
- **食い違いを作った本人へ差し戻す。** 「所有外なので取り込む側で」と言われても、
  **所有ファイルを 1〜3 個足して本人へ返す**ほうが、こちらの指摘より深い直し方が返ります
- **報告を鵜呑みにしない。** 「非コメント行は変更していない」「検査は空振りしない」は
  `diff` と変異で独立に確かめられます。**18 レーン中、申告が誤っていたのは 0 件**でしたが、
  確かめる側が確かめなかった例は 1 件ありました（下記）
- **レビュー指摘は、真偽を確かめてから本人へ返す。** 直近の波で Copilot が 6 件指摘し、
  **5 件は実在、1 件は偽陽性**でした（「正規表現が `_` を扱えない」——文字クラスに `_` が
  入っており、実際に `APP_HOST` の値を変えて赤になることも確かめました）。**偽を本人へ返すと、
  直しようのないものを直させることになります**
- **`gh pr merge` はブランチが worktree に checkout されていると「ローカルブランチを消せない」で
  終わります。** マージ自体は成功しているので、**`gh pr list` で確かめること**（エラー文言だけ
  読んで失敗と判断しない）
- **`gh pr create` の本文に `Closes #NNN` を書く。** 書かないと**マージしても issue が open のまま
  残ります**（直近の 5 件がそうなり、後から手で閉じました）

### 実物を通すまで、動いているかは分からない

**「プレイ経路は本番で動作」と 2 日にわたって報告していたが、実際には動いていなかった**（#180 / #181）。
根拠にしていたのは **`curl` の 200 と CSP の文字列照合**で、**どちらも CORS を評価しない。**

| 検査 | 通してしまうもの |
|---|---|
| CSP の文字列照合・`curl` | **CORS**（評価しない） |
| `SELF.fetch`（vitest の workers pool） | **HTTP のエンコード**（境界を通らない） |

**どちらも「緑だから正しい」と読める形だった。** 実ブラウザを通して初めて見え、しかも
**1 つ目を直した時点で止めていれば 2 つ目を本番でもう一度踏んでいた**（ブラウザ検査の層が
赤のまま残ったことが、それを防いだ唯一の理由）。

**配信を触ったら `scripts/check-sandbox-browser.sh` を回すこと。** 層 0 は**ブラウザ不要**で
30 秒（`GF_SKIP_BROWSER=1`）、しかも**いちばん見えにくい二重圧縮をそこで捕まえる。**

**そして、同じ根で両方向に間違えた。** 「`Accept-Encoding` の有無でサイズが違う」のを
「Cloudflare の再圧縮だろう」と流して二重圧縮を見逃し、直したあとは正しい本文を
「二重圧縮だ」と誤報した。**どちらも「経路が透過的に展開しうる」ことを勘定に入れていない。**

### 変異が当たったことを、変異の結果より先に確かめる

**第 5 波で、こちらが 3 回続けて「緑だから空振りだ」と誤読しかけた。** `sed` の綴りが
本文の整形変更で当たっておらず、**ファイルは変わっていないのに変異したつもりでいた**
（1 回はコメント行だけを書き換えていた）。**md5 か `grep` で当たったことを確かめてから
回すこと。** 当てていない変異の緑は、検査の欠陥ではなく手順の欠陥である。

**同じことを書いた本人が自分で踏んだ例もある。** #26 で足した「既定値が戻っていないこと」の
検査は、設定の読み取りを別ファイルへ移した瞬間に**何も見なくなった**（`process.env[...] ??`
という綴りを探していた）。**綴りを絞った検査は、対象の綴りが変わった日に黙って空振りする。**

### 検査そのものを疑うこと

**緑の検査が何も確かめていないことがあります。** #160 で停止対象を IAM ユーザーからロールへ
移したとき、層 3 の検査は識別子を取れずに**赤**になりましたが、層 2 の検査は**消えた output（空）と
消えた環境変数（空）を突き合わせ、空どうしが一致して緑**でした。**確かめていない検査は、
確かめた証拠として読まれるぶん赤より悪い。**

**移動は 3 点セット（許可・停止・検査）です。** 検査の追随漏れは
`scripts/check-tf-output-refs.sh` が機械で見ます。

## 5. 実測が覆した前提

**issue には起票時の記述が残っています。** 読む人が引っかかる場所なので、ここに一覧を置きます。
根拠は仕様書の該当節にあります。

| 起票時の前提 | 実測 | 記録 |
|---|---|---|
| ビルドの実行環境は VPS | **AWS Lambda** | 確定24 |
| ビルドのタイムアウト 10 秒 | **45 秒**（30 秒では本番で足りず、利用者が踏んだ） | 3.8 / #164 |
| 支配項はコンパイルではなくリンク | **build は vCPU 数にほぼ反比例する** | 1.2.23 |
| brotli は q11 | **q9**（q11 は圧縮だけで 12 秒） | 1.2.21 |
| 作品 1 件 = R2 オブジェクト 1 組 | **共有される** | 確定26 |
| `//go:linkname` は迂回路 | **違う**（`unsafe` を要求するので許可一覧が落とす） | 1.2.26 |
| Cloudflare の待ち時間に上限は無い | **応答を返したあとは 30 秒で切られる**（`waitUntil`）。**ローカルはこの上限をかけない** | 1.2.39 |
| 日次 12 回は生成リクエストの回数 | **LLM 呼び出しの回数** | 1.2.33 |
| 1 生成あたり約 12 円 | **約 16〜18 円** | 4.2 |
| 生成の実行体は Workers | **AWS Lambda**（Pages では 91 秒を持てない） | 1.2.39 / #160 |
| オーケストレータの 600 秒は足りる | **足りない。実際の最悪は 1 依頼 18 回のビルド呼び出しで 1,173 秒**（どの timeout でも Lambda の 15 分に収まらない）。上流を絞って 840 秒 | 3.3 / #174 |
| 開発環境の Go がピン留めとずれている | **ずれていてよい。** 問題は環境ではなく**検査がモジュールの外で版を測っていた**こと | 確定12 / #185 |
| OGP は「初回フレームの静止画」なので軽い | **ヘッドレスブラウザが要る。** Cloudflare 版は Workers 有料プランを要求するので AWS 側へ寄せた | 5.4 / #26 |
| R2 のライフサイクルは未設定 | **既定のマルチパート打ち切りルールが 1 本在った** | 3.7 / #31 |
