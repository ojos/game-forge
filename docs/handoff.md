## 3. 触るときの注意

- **生成経路は課金されます。** サブエージェントには「`/api/generate` を実際に呼ばない」と
  明示すること。テストは経路層のハンドラを直接叩きます
- **本番 D1 のマイグレーションは手作業です。** デプロイでは走りません（[pages-deploy.md](pages-deploy.md)）。
  2026-08-28 に `0002`〜`0005` が未適用のまま本番が動いており、`build_cache` が無いせいで
  生成が 1 回、**課金だけして落ちました**（16.75 円）。この失敗は `kind='build'` ではないので
  リトライに入らず 500 になります。**スキーマに触る PR を入れたら
  `npx wrangler d1 migrations list DB --remote --env production` を見ること**
- **`migrations/0006_games_preview_key.sql` は本番 D1 へ未適用です。** `feat/28-sandbox-delivery`
  にあり、マージしたら適用が要ります。**適用しないと配信経路が `no such table` ではなく
  `no such column` で落ちます**（0002〜0005 で踏んだのと同じ罠）
- **Bedrock の鍵は Active です。** 止めるなら
  `aws iam update-access-key --user-name game-forge-bedrock-invoker --access-key-id <id> --status Inactive`
- **本番 D1 への書き込みは拒否されることがあります**（実行環境の判定）。都度の承認を得ること。
  **読み取り（SELECT）は通りますが、`migrations apply` は承認を得ても classifier が止めます。**
  利用者が自分の端末で叩くのが早いです
- **AWS SSO は切れます。** `aws sso login --profile game-forge-prod --use-device-code`
- **GCP の ADC も切れます。** `gcloud auth application-default login --no-launch-browser` のあと、
  **必ず `ido@ojos.jp` であることを確認**すること。別アカウントでも認証は成功し、
  `terraform plan` が権限エラーになるまで気づけません（[gcp-oauth-setup.md](gcp-oauth-setup.md)）
- **仕様の古い記述は削らず、注記を足して残します**
- **マージは squash のみ。利用者の明示的な指示があるまでマージしません**

## 4. 並列作業のやり方

worktree とサブエージェントで **3 レーンまで同時に走らせて成立しました**（2026-08-28）。
**2 回目は衝突が 1 件も出ませんでした**（下の追記）。

- **所有ファイルを重ねない。** レーンごとに明示して渡す
- **`docs/product-spec.md` の版行 2 行は誰にも触らせない。** 取り込む側が版と節番号を付ける
- **マイグレーションの連番は先に割り当てる**（`0004_` は誰、`0005_` は誰）
- **worktree を消さない。** 消すとレビュー指摘の差し戻しができなくなります
- **レビュー指摘は書いた本人へ差し戻す。** 変異検査の型を持っているので直りが速く、質も高い
- **同じ継ぎ目を 2 レーンが触る場合は、結線だけを最後の 1 本にまとめる**
  （`defaultPipeline` は 4 行のオブジェクトで、2 レーンが同時に足すと必ず衝突します）

**2 回目（#28 / #29 / #24 / #101）で効いたこと。衝突ゼロでした。**

- **`docs/product-spec.md` を誰にも編集させず、文面だけ報告させた。** 版行と節番号は取り込む
  側が付ける規約の徹底で、前回唯一の衝突点がこれで消えました。仕様の反映は最後に
  1 本のブランチ（`docs/spec-v1.31`）で行い、8 か所をアンカー一致で差し込みました
  （一致数が 1 でなければ落とす形にすると、節の移動に気づけます）
- **1 つの継ぎ目を触る 2 issue は同じレーンに畳む。** #28 と #29 はどちらも配信の
  レスポンス組み立てを書き換えるので、分けたら必ず衝突しました。**1 issue = 1 PR は
  守りつつ、worktree は 1 つ**にして直列に出させます
- **「自分が作った食い違いは自分の PR で閉じる」を差し戻しの原則にする。** 3 レーンとも
  「所有外なので取り込む側で直してほしい」と申し送ってきましたが、事実と違う記述を一度
  main へ入れると、その間に読んだ人が誤ります。所有ファイルを 1〜3 個足して本人へ返すと、
  **こちらの指摘より深い直し方**（写しをやめる、検査で塞ぐ）が返ってきました
- **サブエージェントの報告を鵜呑みにしない。** 「非コメント行は変更していない」といった
  主張は `diff` で独立に確認できます。今回は 3 レーンとも申告どおりでした
