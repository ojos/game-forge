## 1. 回す前に

| 確かめること | 値 |
|---|---|
| ログインしているアカウント | **運営（`game-forge@ojos.jp`）**。個人アカウントで回すと所有者が変わる |
| 日次の生成枠 | **利用者ごとに 10 回/日。** 運営アカウントには別に 10 回付くので、個人枠は減らない |
| 試行回数 | **最大 2 回**（`MAX_GENERATION_ATTEMPTS`）。**固定ではない**——1 回目のビルドが通れば 1 回で終わり、**やり直せる失敗のときだけ 2 回目が走る**。日次枠は**課金された LLM 呼び出し**を数える（`src/quota.ts`） |
| 費用 | **1 回の呼び出しにつき約 ¥22.41**（実測）。**10 本なら最低 ¥224、全部が 2 回目まで走ると最大 ¥448。** 見込みではなく**幅**として持つこと |
| お題の文字数 | **2,000 字**（`MAX_PROMPT_LENGTH`）。**貼る文面に効くのはこちら** |
| 生成ソースの上限 | **64KB**（`MAX_SOURCE_BYTES` / #284）。**これは生成される Go のソースの上限で、貼る文面とは別** |

**画面から 1 本ずつ回します**（`/generate`）。**実行環境（AI エージェント）は `/api/generate` を
呼びません**——課金されるため、`docs/handoff.md` 3 章で禁じています。

## 2. お題（そのまま貼る）

**方針は「機構はプレーンに保ち、具体にするのは自機と敵だけ」です。** ステージ数・物語・特殊
ルールは書きません。**足りないものが目に見える状態が、そのままツッコミどころと改造余地に
なります**（#43）。

**参考作の名前は書きません。** 骨組みは指定側（このお題）が持ちます。

## 3. 1 日目が終わったらやること

**2 日目の構成は、1 日目の実測で決め直します**（#43）。1 日目に測るのは次の 3 つです。

1. **実際のソース量**（64KB に対する余裕）
2. **所要時間**（1 本あたり。**送信から完成までの実測は 107 秒**——ただしこれは 2026-08-30、
   64KB へ上げる前の値である。時間予算の現行値は仕様 4.4 を見ること）
3. **費用**（`docs/usage-report.md` と `scripts/usage-report.sh`）

**6 がモデレーションで落ちた場合は、仕様 8.2 の実測表へ 1 行足してください**（暴力・不品行の
フィルタを外した v1.47 以降で落ちた初の記録になります）。

## 4. 公開と、そのあと

- **生成しただけでは誰にも見えません。** 作者プレビューで試遊し、**「公開」を押すまで URL は
  有効になりません**（5.4）。10 本とも公開すること
- **公開すると OGP を 1 回だけ撮ります**（5.4 / `docs/ogp-capture.md`）。撮影は 7.9〜16.9 秒で
  ぶれるので、`ogp_state` が `ready` になったかを確かめる
- **公開すると、トップの「公式サンプル」の節に出ます**（2.3.1 / 2.3.3。運営フラグが立っているため）。
  **ただし最大 60 秒遅れます**——トップは引いた行を Cache API に載せており（`HOME_CACHE_KEY` /
  `LIST_CACHE_TTL_SECONDS = 60`）、**公開直後は前の一覧が返りえます**。**節に出るのは各 8 件まで**
  なので、10 本すべては並びません
- **作品ページに「運営アカウント」のバッジが出ます**（#334。公開済みの作品だけ）

## 5. 音

**音は本番で鳴ります**（#306 は解決済み。2026-09-05 に利用者が確認）。**サンプルに音入りが
1 本も無いと、鳴ることが誰にも伝わりません。** 生成後に音が入っているかを見て、入っていない
なら**改造（フォーク）で足す**という手もあります（**フォークも同じ生成の経路を通るので、1 回の
要求につき最大 2 回の課金された呼び出しと、そのぶんの日次枠を使います**）。
**8 と 5 は音と相性が良い**（#43）。

### 1 章の見込みとの差

- **費用は幅（¥224〜¥448）の下端に近い。** 1 呼び出しあたり **¥17.26** で、見込みの ¥22.41 を
  下回った。**呼び出しが 10 回を超えた 5 回は、2 回目の試行 3 回・作り直し 1 回・推敲 1 回**である
- **ソースは 10〜18KB で、64KB の 3 割に届かない。** 最重量と見ていた 7 も 14.7KB、いちばん
  大きかったのは 3（17.8KB）。**「2 日目の構成を実測で決め直す」必要は結果として無かった**
- **モデレーションで落ちた回は 0 回。** 6（格闘の骨組み）も通ったので、**8.2 の実測表へ足す行は無い**
- **所要時間は測っていない。** 台帳にはビルドの時間が入らない（ビルド側は
  `scripts/build-time-report.sh`）

### 音と入力

- **10 本とも `ebiten/v2/audio` を import している。** **実際に鳴るかは、この照合では確かめていない**
  （import は鳴ることの証拠にならない）
- **マウスを読むのは 10（モグラぽん）のほかに 5 と 8 の計 3 本**（`CursorPosition` / `IsMouseButton*`）

### 残ったもの

- **3 の 1 回目の下書き**（`91de0745-7ca6-4478-8ba9-6431b5f92883`。`generation_state = failed` /
  `generation_error = build-failed`）が `draft` のまま残っている。**公開されない下書きは 14 日で
  自動削除される**（3.7）ので、手で消さない
- **日次枠が 1 回はみ出した。** 9/13 の運営アカウントの呼び出しは **11 回**で、上限の 10 回を
  超えている。**枠の判定は要求の手前で 1 回だけ**（`src/quota.ts` の `generationQuotaStatus`。
  `calls >= DAILY_QUOTA_PER_USER` で止める）なので、**9 回使った時点で始めた要求（4）が 2 回試行して
  11 回になった。** 1 人・1 日の上振れが最大で 1 回ぶん大きいことになる。**仕様にもコメントにも
  この挙動は書かれていない**（別 issue で扱う）
