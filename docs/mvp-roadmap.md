## M0 前提の確定

仕様書 12 章の未確定事項は、いずれも「決めていないまま実装すると手戻りになる」性質のもの。shared-ai-rules 11 章に従い、実施タスクではなく**確認タスク**として起票する。

### M0-1 プロダクト名とサンドボックス専用ドメインを確定する
- **goal:** プロダクト名を 1 つに決め、あわせてユーザー生成コンテンツ配信用の別オリジンドメインを確定・取得する。
- **scope.in:** 候補（PromptArcade / BitPrompt）の商標・ドメイン空き調査、名称決定、サンドボックス用ドメインの取得。
- **acceptance:** 仕様書 12 章 #1 が削除され 1 章に確定名が記載されている / サンドボックス用ドメインが取得済みで DNS が引ける。
- **priority:** high（M4-3 の CSP・オリジン設計をブロックする）
- **参照:** 12-#1 / 3.1 / 7.2

### M0-2 R2・D1 の現行単価と無料枠を実測し、未公開成果物の保持日数を決める
- **goal:** 3.6 / 3.7 のコスト前提を着手時点の実値で確定し、ライフサイクルルールの N 日を決める。
- **scope.in:** R2 の保存量・オペレーション単価、D1 の読み書き無料枠の現行値確認。1 本あたり容量（2〜3MB＋10〜30KB）からの月額試算。未公開成果物の保持日数 N の決定。
- **acceptance:** 仕様書 12 章 #3・#5 が削除され、3.6 / 3.7 に実値と N が記載されている。
- **priority:** high（M4-6 のライフサイクル設定をブロックする）
- **参照:** 12-#3 / 12-#5 / 3.6 / 3.7

### M0-3 Go のピン留めバージョンを確定する
- **goal:** ビルドサーバーで使う Go のバージョンを 1 つに固定し、更新手順を 3.5 と連動させる。
- **scope.in:** Ebitengine の対応状況確認、バージョン決定、`wasm_exec.js` の出し分け方針の確定、更新手順の文書化。
- **acceptance:** 仕様書 12 章 #4 が削除され、3.5 / 3.8 にバージョンと更新手順が記載されている。
- **priority:** high（M2-4 の Dockerfile をブロックする）
- **参照:** 12-#4 / 3.5 / 3.8

### M0-4 count_tokens で 1 生成あたりのコストを実測し、日次クォータ値を逆算する
- **goal:** Sonnet 5 の新トークナイザによる実トークン数を測り、4.2 の試算を実値へ置き換えたうえで日次クォータを決める。
- **scope.in:** システムプロンプト草案と代表的な親ソースを `count_tokens` で実測。`effort=high` / `medium` での出力トークン実測。月 1 万円からの生成回数逆算。招待者数の想定から日次クォータ値を決定。
- **acceptance:** 仕様書 12 章 #6 が削除され、4.2 の表が実測値に更新され、4.3 に日次クォータの具体値が記載されている。
- **priority:** high（M3-2 の判定値をブロックする）
- **参照:** 12-#6 / 4.1 / 4.2 / 4.3

### M0-5 ソースサイズ 30KB 超過時の挙動を決める

## M1 認証と招待

### M1-1 D1 スキーマの初期マイグレーション

- **scope.in:** マイグレーションファイル、`games.parent_id` のインデックス、`fork_count` の非正規化列、ローカル D1 への適用手順。

- **priority:** high
- **参照:** 5.1 / 3.6

### M1-2 Google OAuth ログインと署名付き Cookie セッション
- **goal:** Google OAuth のみでログインでき、Workers 側で署名付き Cookie のセッションを維持する。
- **scope.in:** OAuth コールバック、`users` 行の作成（`google_sub` 一意）、Cookie（`HttpOnly` / `Secure` / `SameSite=Lax`）の発行・検証、ログアウト。
- **acceptance:** 署名検証を含むセッションの単体テストが通る / 改竄した Cookie が拒否される / クライアントシークレットがリポジトリに存在しない（`check-no-secrets.sh` が PASS）。
- **priority:** high
- **参照:** 8.1 / 確定9

### M1-3 招待コードの発行・検証・使用済み管理
- **goal:** 既存参加者へ招待枠を付与し、コードの発行・検証・使用済み化を行う。
- **scope.in:** `invites` の CRUD、コード生成（推測困難）、`expires_at` 判定、`used_by` / `used_at` の記録、二重使用の防止、招待枠の残数管理。
- **acceptance:** 同一コードの二重使用が拒否されるテストが通る / 期限切れコードが拒否されるテストが通る / `users.invited_by` が記録される。
- **priority:** high
- **参照:** 8.1 / 7.3 / 11.1

### M1-4 登録フローの結線と待機リスト登録
- **goal:** 「招待コード検証 → Google OAuth」の順で登録が完了し、未招待ユーザーは待機リストへ導線が変わる。
- **scope.in:** 登録画面、コード検証を先に置くフロー、未招待時の待機リスト登録フォームと保存先。
- **acceptance:** 無効コードでは OAuth 画面に到達しないことを検証する E2E テストが通る / 待機リスト登録が保存され、登録数を取得できる。
- **priority:** high
- **参照:** 8.1 / 2.2-4 / 10.2

## M2 生成パイプライン

### M2-1 Workers の生成エンドポイントとリクエスト検証
- **goal:** 認証済みセッションからの生成リクエストを受け付ける入口を作る。
- **scope.in:** エンドポイント定義、セッション必須の検証、プロンプト長の上限、リクエストスキーマ検証、3.3 の順序に沿ったオーケストレーションの骨組み。
- **acceptance:** 未認証リクエストが 401 で拒否されるテストが通る / スキーマ違反が 400 で拒否される。
- **priority:** high
- **参照:** 3.3 / 5.2

### M2-2 Anthropic API 呼び出しとシステムプロンプトの策定
- **goal:** 6.1 の制約を含むシステムプロンプトで Sonnet 5 を呼び出し、`usage` を取得する。
- **scope.in:** システムプロンプト本文（`ebiten.Game` の厳格実装 / 外部ファイルロード禁止 / `fmt`・`reflect` 禁止 / 許可パッケージのホワイトリスト / 30KB 上限）、`system` へのキャッシュブレークポイント配置、`usage` 4 種の取得。
- **acceptance:** システムプロンプトに動的値が含まれないことを検証するテストが通る / 2 回目以降の呼び出しで `cache_read_input_tokens` が 0 より大きい / `usage` 4 種が呼び出し結果に含まれる。
- **priority:** high
- **参照:** 6.1 / 4.5 / 4.1
- **依存:** M0-4

### M2-3 AST によるパッケージホワイトリスト検査
- **goal:** 生成された Go ソースの import を AST で解析し、ホワイトリスト外を拒否する。
- **scope.in:** AST パース、import 抽出、ホワイトリスト定義（6.1 のプロンプトと一致させる）、違反時は再生成に回さず即拒否。
- **acceptance:** `os/exec` を含むソースが拒否されるテストが通る / ホワイトリストがプロンプト側の記載と機械照合され、不一致で落ちる（shared-ai-rules 12 章「一覧の複製は機械照合で担保する」）。
- **priority:** high
- **参照:** 5.2-5 / 7.1 / 6.1

### M2-4 隔離ビルドコンテナの Dockerfile と自動デプロイ
- **goal:** 7.1 の封じ込め要件を満たすビルドイメージを作り、VPS へ自動デプロイする。
- **scope.in:** Dockerfile（Go バージョン固定、Ebitengine の vendor 焼き込み、`/src` への配置、`/cache` の作成と chown 65534）、エントリポイントの `/src`→`/work` コピー、`docker run` オプション一式、`.github/workflows/deploy-compiler.yml` による SSH デプロイ。
- **acceptance:** `--network=none --read-only` の指定でサンプルソースのビルドが成功する / `--user 65534` で `permission denied` が出ない / コンテナ内から外部ネットワークへ到達できないことを検証する / `main` への push でイメージが更新される。
- **priority:** high
- **参照:** 7.1 / 3.8 / 9
- **依存:** M0-3

### M2-5 VPS ビルド API（同時実行制御・タイムアウト・結果キャッシュ）
- **goal:** Workers からのビルド依頼を受け、1 リクエスト 1 コンテナ使い捨てで処理する API を用意する。
- **scope.in:** Worker Pool による並列数制限、10 秒タイムアウト、生成ソースのコンテンツハッシュによるビルド結果キャッシュ、`GOCACHE` / `GOMODCACHE` の永続ボリューム、Workers からの認証。
- **acceptance:** 10 秒を超えるビルドが打ち切られるテストが通る / 同一ソースの 2 回目がキャッシュヒットする / 並列数上限を超えるリクエストがキューイングされる。
- **priority:** high
- **参照:** 3.8 / 7.1

### M2-6 コンパイル失敗時の自動リトライ
- **goal:** ビルド失敗時にエラー出力を LLM へ返し、最大 2 回まで自動で再生成する。
- **scope.in:** エラー出力の整形と再投入、リトライ上限、各試行を `generations` に 1 行ずつ記録、上限到達時のユーザー向けメッセージ。
- **acceptance:** 常に失敗するソースで試行が 3 回（初回＋2）で打ち切られるテストが通る / 各試行が `generations` に記録され `succeeded` が正しい。
- **priority:** high
- **参照:** 5.2-7 / 4.3

### M2-7 R2 への書き戻しと games 行の作成
- **goal:** ビルド成果物を VPS から R2 へ直接書き込み、`games` 行を `draft` で作成する。
- **scope.in:** VPS からの S3 互換 API 書き込み（`.wasm.br` と `source.go`）、オブジェクトメタデータへの `Content-Type: application/wasm` と `Content-Encoding: br` の設定、`games` 行の作成（`go_version` / `source_key` / `wasm_key`）。
- **acceptance:** R2 認証情報が VPS 側のみに存在し、ブラウザ・コンテナへ渡らないことを確認する / 書き込んだオブジェクトの両ヘッダが取得できる / `games` 行が `status='draft'` で作成される。
- **priority:** high
- **参照:** 3.3-6 / 3.4-1 / 5.1

## M3 費用ガード

**本マイルストーンは仕様書 4 章の「中核要件」に対応する。M2 が動いた時点で、これが無いと上限のない従量課金が走る。**

### M3-1 費用台帳への全件記録と円換算
- **goal:** すべての LLM 呼び出しの `usage` を円換算し、成功・失敗・リトライを問わず `generations` へ記録する。
- **scope.in:** `usage` 4 種の取得、単価テーブル（導入価格 / 通常価格の切り替えを含む）、円換算、`cost_jpy` の記録、月次累計の集計クエリ。
- **acceptance:** 失敗した生成も 1 行記録されるテストが通る / リトライ 3 試行で 3 行記録される / 既知の `usage` 入力に対する円換算値が期待値と一致する。
- **priority:** high
- **参照:** 4.3 / 5.1

### M3-2 日次クォータと月次上限の判定
- **goal:** 生成リクエストの受付前に日次クォータと月次 1 万円上限を判定し、超過なら即座に拒否する。
- **scope.in:** 3.3-2 の位置での判定、日次カウント、月次累計と 1 万円の比較、80% 到達時の警告、100% 到達時の生成停止。
- **acceptance:** 累計が上限を超えた状態で生成リクエストが LLM 呼び出しに到達せず拒否されるテストが通る / 80% で警告フラグが立つ / 日次上限超過が翌日リセットされる。
- **priority:** high
- **参照:** 4.3 / 3.3-2
- **依存:** M0-4, M3-1

### M3-3 生成枠と停止状態の UI 表示
- **goal:** 残枠と停止状態を UI に常時露出させ、「押しても動かないボタン」を無くす。
- **scope.in:** 「本日の残り生成枠 N 回」の常時表示、日次枠終了時の翌日再開時刻の提示、月次上限到達時のメッセージ（プレイと共有は継続できる旨）、VPS 停止時の「生成停止中」表示（degrade）。
- **acceptance:** 各状態のスナップショットテストが通る / 月次上限到達時もプレイ導線が操作可能である。
- **priority:** high
- **参照:** 4.4 / 3.8

### M3-4 effort の A/B 計測
- **goal:** `effort=high` と `medium` を比較し、生成成功率とコストの両面で採用値を決める。
- **scope.in:** `effort` の切り替え機構、割り当てと結果の記録、初回コンパイル成功率と 1 生成あたり実コストの集計。
- **acceptance:** 両群の実コストと初回コンパイル成功率を出力する集計クエリが動く / 採用値の決定が仕様書 4.2 へ反映される。
- **priority:** medium（4.2 が「最優先の実験項目」とする一方、計測には生成量が要るため M3 完成後に回す）
- **参照:** 4.2 / 10.2

## M4 公開とプレイ

### M4-1 公開フローと OGP 画像生成
- **goal:** 作者が試遊して「公開して共有」を押すまで URL を無効にし、公開時に OGP 画像を生成する。
- **scope.in:** `draft` → `published` の状態遷移、`published_at` の記録、試遊画面の主ボタン、OGP 画像（初回フレームの静止画 1 枚）の公開時遅延生成と保存。
- **acceptance:** `draft` の公開 URL が 404 になるテストが通る / 未公開作品の OGP 生成が実行されない / 公開後に OGP メタタグが正しい URL を返す。
- **priority:** high
- **参照:** 5.4 / 11.2 / 確定4

### M4-2 作者プレビューの権限制御配信
- **goal:** `draft` の作品を作者だけがプレビューできるようにする。
- **scope.in:** Workers 経由の所有者チェック、R2 からの取得と返却、または推測不能なランダムキーによる unlisted 配信。
- **acceptance:** 他人の `draft` へのアクセスが 403 になるテストが通る / 作者本人は 200 で取得できる。
- **priority:** high
- **参照:** 5.4

### M4-3 サンドボックス専用ドメインからの配信と CSP
- **goal:** ユーザー生成コンテンツを親と別オリジンの iframe で実行し、外部通信を全面的に塞ぐ。
- **scope.in:** サンドボックス専用ドメインからの配信、`iframe sandbox="allow-scripts"`（`allow-same-origin` と `allow-popups` は付けない）、`connect-src 'none'` を含む Strict CSP、COEP / CORP と `credentialless` の検討。
- **acceptance:** 配信オリジンが親と異なることを検証するテストが通る / iframe 内からの `fetch` が CSP で遮断されることを確認する / `allow-same-origin` が付いていないことを検証する。
- **priority:** high
- **参照:** 7.2 / 3.1
- **依存:** M0-1

### M4-4 Wasm 配信の最適化
- **goal:** タップから数秒でプレイ開始できるよう、3.4 / 3.5 の配信仕様を実装する。
- **scope.in:** Brotli 事前圧縮、`Content-Type: application/wasm` と `Content-Encoding: br` の両方の付与、`WebAssembly.instantiateStreaming` によるロード、ビルドフラグ `-ldflags="-s -w"`、`go_version` に応じた `wasm_exec.js` の出し分け。
- **acceptance:** 配信レスポンスに両ヘッダが含まれることを検証するテストが通る / `instantiateStreaming` がフォールバック経路に落ちないことを確認する / 圧縮後サイズが 3MB 以下である。
- **priority:** high
- **参照:** 3.4 / 3.5
- **依存:** M0-3

### M4-5 ロード中画面
- **goal:** 数秒のロード時間を「空白」ではなく「文脈の提示」に変える。
- **scope.in:** OGP スクリーンショット・作者名・親ゲーム名・「改造する」ボタンの先行表示、ロード進捗の提示。
- **acceptance:** Wasm のロード完了前に 4 要素すべてが描画されることを検証するテストが通る。
- **priority:** medium
- **参照:** 3.4-5 / 2.2-2

### M4-6 R2 ライフサイクルルール
- **goal:** 未公開のまま N 日経過した成果物を自動削除し、保存量が公開本数と乖離しないようにする。
- **scope.in:** R2 のライフサイクルルール設定、`draft` のまま残った `.wasm.br` と `source.go` の削除、削除対象と保持対象の切り分け。
- **acceptance:** ライフサイクルルールが設定済みであることを確認できる / 公開済み作品が削除対象に含まれないことを確認する。
- **priority:** high（3.7 が「最初から設定する」ことを求めている）
- **参照:** 3.7 / 5.4
- **依存:** M0-2

## M5 フォークと系統

**本マイルストーンがコア仮説（フォーク連鎖）の実体である。M7 の主 KPI はここが動かないと測定できない。**

### M5-1 フォーク生成（親ソース＋差分プロンプト）
- **goal:** 公開作品の最終ソースを読み込んだ状態でエディタを起動し、差分プロンプトから全文再出力で再生成する。
- **scope.in:** R2 からの親 `source.go` 取得、`messages` 先頭ブロックへの配置と別キャッシュブレークポイント、差分プロンプト UI、`games.parent_id` の記録、単一親ツリーの維持。
- **acceptance:** 生成された子の `parent_id` が親を指すテストが通る / 親ソースが `messages` の先頭に置かれ、同一親の 2 回目で `cache_read_input_tokens` が 0 より大きい / 親が `published` でない場合にフォークが拒否される。
- **priority:** high
- **参照:** 5.3 / 4.5 / 確定3

### M5-2 ソースサイズ 30KB 上限の適用
- **goal:** フォーク連鎖によるソース肥大化を 30KB で止め、M0-5 で決めた超過時の挙動を実装する。
- **scope.in:** 生成前後のサイズ検査、超過時の挙動（M0-5 の決定に従う）、ユーザー向けメッセージ。
- **acceptance:** 30KB を超えるソースで M0-5 の決定どおりの挙動になるテストが通る。
- **priority:** medium
- **参照:** 5.3 / 6.1
- **依存:** M0-5

### M5-3 系統の近傍表示
- **goal:** 作品ページに親 1 リンクと子のリストを表示し、系統をたどれるようにする。
- **scope.in:** 「元ゲーム: ○○」の 1 リンク、「このゲームからの改造: N 件」（`published` のみ・新しい順・20 件＋もっと見る）、`fork_count` の非正規化更新。
- **acceptance:** `draft` の子が一覧に出ないテストが通る / `fork_count` が実件数と一致する / 21 件目が「もっと見る」で取得できる。
- **priority:** high
- **参照:** 5.5 / 5.1 / 確定10

### M5-4 親の tombstone 化
- **goal:** 親を削除しても子を巻き込まず、「削除済みの作品から派生」と表示する。
- **scope.in:** 物理削除ではなく `status='removed'` への遷移、子側の表示、連鎖削除を行わないことの明示。
- **acceptance:** 親を削除しても子が `published` のまま残るテストが通る / 子の作品ページに「削除済みの作品から派生」が表示される。
- **priority:** medium
- **参照:** 5.3

### M5-5 改造通知メールの送信
- **goal:** 自分の作品が改造されたとき、作者にメールを 1 通送る。
- **scope.in:** フォーク公開時のトリガ、宛先の解決、本文（改造者名・子作品 URL）、1 フォークにつき 1 通の重複防止、送信失敗時のログ。
- **acceptance:** フォークの公開でメールが 1 通だけ送られるテストが通る / 自分自身のフォークでは送られない / 本文に機密が含まれない。
- **priority:** high（2.2-6 が「これがないとコア体験ループが閉じない」としている）
- **参照:** 5.5 / 2.2-6
- **依存:** M0-6

## M6 安全と運用

### M6-1 入力側モデレーション
- **goal:** 危険度の高いプロンプトを LLM 呼び出しの前に遮断する。
- **scope.in:** Gemini Safety Settings または OpenAI Moderation API の選定と組み込み、遮断時のユーザー向けメッセージ、遮断ログ。
- **acceptance:** 既知の危険プロンプトが LLM 呼び出しに到達せず遮断されるテストが通る / 遮断が生成枠を消費しない。
- **priority:** high
- **参照:** 8.2 / 5.2-2

### M6-2 出力側の文字列リテラル検査
- **goal:** 生成コード内の文字列リテラルを抽出し、NG ワード検査を行う。
- **scope.in:** AST からの文字列リテラル抽出（M2-3 のパース結果を再利用）、NG ワードリスト、違反時の扱い、リストの管理方法。
- **acceptance:** 差別語を `text` 描画するソースが検出されるテストが通る / 検査が M2-3 と同一の AST パースを共有している。
- **priority:** high
- **参照:** 8.3 / 5.2-5

### M6-3 著作権・有名IP 回避ガードレール
- **goal:** 著名 IP 名を含む入力を拒否せず、安全なパロディへ自動置換し、置換したことをユーザーへ開示する。
- **scope.in:** システムプロンプトへの自動変換ルールと命名規制（`player` / `hero` / `enemy` 等）の追加、置換の検出と開示 UI。
- **acceptance:** 著名 IP 名を含む入力で生成が拒否されず、置換が行われるテストが通る / 置換時に開示メッセージが表示される / 生成コードに商標固有名詞の変数名が含まれない。
- **priority:** medium
- **参照:** 6.2 / 6.1

### M6-4 通報の受付・審査キュー・BAN 運用
- **goal:** ワンタップ通報を受け付け、閾値到達時は自動非表示ではなく審査キューへ投入する。
- **scope.in:** 通報 UI と `reports` への記録、閾値判定、審査キューと運用画面、新規露出のみ停止する運用の実装、`google_sub` 単位の BAN と招待元の招待枠停止。
- **acceptance:** 閾値到達で自動非表示にならず審査キューへ入るテストが通る / BAN されたユーザーが生成できない / BAN 時に招待元の招待枠が停止する。
- **priority:** high
- **参照:** 8.4 / 7.3 / 5.1

### M6-5 利用規約・削除申請フォーム・送信防止措置の記録
- **goal:** フォーク機能の法的基盤を整え、削除申請と送信防止措置の記録を運用に乗せる。
- **scope.in:** 利用規約（改変・再配布の許諾条項、生成物の権利帰属と非独占の利用許諾、即時削除権限）、フッターへの権利者向け削除申請フォーム常設、送信防止措置の手順書と記録の保存先。
- **acceptance:** 規約にフォーク許諾条項と権利帰属条項が含まれている / 削除申請フォームが全ページのフッターから到達できる / 送信防止措置の記録が追記のみの形式で保存される。
- **priority:** high（5.6 が「MVP でも省略できない」としている）
- **参照:** 5.6 / 8.4

## M7 β開始と計測

### M7-1 KPI 計測基盤
- **goal:** 主 KPI のフォーク率と補助指標を、いつでも取得できる形にする。
- **scope.in:** フォーク率（フォーク生成数 ÷ 全生成数）、3 世代以上の系統の本数、招待者あたりの生成数、「改造する」を押した未招待ユーザー数と待機リスト登録率、1 生成あたり実コスト、初回コンパイル成功率。3.6 に従い集計はバッチで行い、リクエスト毎の D1 書き込みを増やさない。
- **acceptance:** 6 指標すべてを出力する集計が動く / 集計が D1 の書き込みを増やさない（読み取りのみ、またはバッチ 1 回）。
- **priority:** high
- **参照:** 10.1 / 10.2 / 3.6

### M7-2 コールドスタート用サンプル 10 本の作成
- **goal:** ツッコミどころと改造余地のある初期サンプルを 10 本公開する。
- **scope.in:** 題材の決定（「ゴリラソーダ」「10 秒で地球破壊」「逆・弾幕シューティング」「単位落とすな留学生」等）、生成・試遊・公開。**リトライ込みで約 15 回＝ほぼ 1 日分の生成枠を消費するため、実施日を枠計画に含める。**
- **acceptance:** `published` の作品が 10 本存在する / 消費した生成回数と費用が台帳から確認できる。
- **priority:** medium
- **参照:** 11.3 / 4.3

### M7-3 撤退条件の判定手順と 3 ヶ月レビューの設定
- **goal:** 撤退条件を「決めていない状態」にしないため、判定日と判定手順を先に固定する。
- **scope.in:** 開始日の定義、3 ヶ月後の判定日の設定、判定に使う指標（フォーク率 40% 未満 / 3 世代以上の系統が 0 本）の取得手順、判定結果の記録先。
- **acceptance:** 判定日が明記され、判定に使う集計が M7-1 の出力で賄えることを確認できる / 判定結果の記録先が決まっている。
- **priority:** medium
- **参照:** 10.3 / 10.2

## 起票時の共通事項

- 各 issue の本文には、本文書の該当節（goal / scope.in / acceptance / priority / 参照）をそのまま転記する。
- ラベルは既存の `enhancement`（実装）、`documentation`（M0 の確認タスクと M6-5）を使う。新規ラベルは作らない。
- issue 本文に機密（`.env` の値、`GH_TOKEN`、R2 認証情報、OAuth クライアントシークレット）を含めない。
- 依存関係は issue 本文の「依存」行で示す。GitHub の依存機能は使わない。
