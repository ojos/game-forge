## 1. 現在地

**生成は本番で動いており、利用者は送信したらタブを閉じてよくなりました。**

```
/generate → クォータ判定 → games 行を作る → 202 と URL を返す（約 0.5 秒）
                                      ↓ 非同期
        [オーケストレータ Lambda] 生成 → 台帳 → import 検査 → ビルド関数 → R2
                                      ↓ コールバック
                              games 行を完成（preview_key が入る）
```

**実測（2026-08-30）: 送信から完成まで 107 秒、1 回 18.49 円。** 利用者は待ちません。

- **接続を切っても完走することを本番で確認済み**（タブを閉じ、あとから `/works/<id>` を開き直した）
- **プレイ経路も本番で動いています。** ただし**ここへ来るまでに 2 つの不具合を踏みました**（#180 / #181）。
  経緯は 4 章「検査そのものを疑うこと」を読んでください
- **メールも届きます**（#178。DKIM / SPF / DMARC はすべて `game-forge.ojos.jp` のゾーン内で完結。
  `ojos.jp` には 1 本も置いていません）
- 実行体の設計と経緯は仕様 1.2.39 と [orchestrator.md](orchestrator.md) にあります

### ★ 公開する手段がまだありません

**すべての作品が `draft` のままです。** 公開フロー（**#26 / M4-1**）が未実装で、`status='published'` にする経路がありません。

したがって **`/g/<game_id>/` は誰にも使えず**、作者が unlisted な `/p/<preview_key>/` を手で配る以外に共有の方法がありません。**招待した方に「作って、遊んで、共有する」を体験してもらうには #26 が要ります。**

**#26 が入れば #30（ロード中画面）が解け、M5 のフォーク連鎖＝コア仮説に入れます。**

## 3. 触るときの注意

- **生成経路は課金されます。** 1 回 **約 16〜19 円**（実測 15.80 / 16.75 / 18.49 円）。サブエージェントには「`/api/generate` を
  実際に呼ばない」と明示すること。テストは経路層のハンドラを直接叩きます
- **本番 D1 のマイグレーションは手作業です。** デプロイでは走りません。**スキーマに触る PR を
  入れたら `npx wrangler d1 migrations apply DB --remote --env production` を忘れないこと**
  （0002〜0005 を忘れて 16.75 円を捨てた前例があります）
- **実行環境は本番への書き込みを止めます。** 読み取り（SELECT・CloudWatch・terraform plan）は
  通りますが、`migrations apply` / `terraform apply` / R2 への書き込みは**利用者の端末**で叩きます
- **エッジの長命 AWS 鍵は `BUILD_AWS_*` の 1 組だけ**になりました（#160）。できるのは
  「オーケストレータへジョブを 1 回投げる」ことだけです。**`BEDROCK_AWS_*` は削除済み**
- **利用者の端末は macOS です。** スクリプトに GNU 拡張（テンプレート無しの `mktemp`、
  `date +%N`、`sha256sum`、GNU sed の `\x`）を書かないこと。`scripts/check-shell-portability.sh`
  が表にある綴りを落としますが、**網羅ではありません**（表は踏んだ事故を足していく形）
- **`mapfile`（bash 4+）依存が残っています。** macOS の `/bin/bash` は 3.2 です。利用者が
  自分の端末で外部層を回すと落ちます。未対応
- **AWS SSO と GCP の ADC は切れます。**
  `aws sso login --profile game-forge-prod --use-device-code` /
  `gcloud auth application-default login --no-launch-browser`。**GCP は認証後に
  `ido@ojos.jp` であることを必ず確認**（別アカウントでも成功し、`terraform plan` が
  権限エラーになるまで気づけません）
- **terraform を叩くときは `CLOUDFLARE_API_TOKEN` を載せること**（`set -a; . scripts/load-project-env.sh; set +a`）。
  載せ忘れると R2 のリソースの読み戻しが 9106 で落ち、**プロバイダの不具合に見えます**
- **仕様の古い記述は削らず、注記を足して残します**
- **マージは squash のみ。利用者の明示的な指示があるまでマージしません**

## 4. 並列作業のやり方

worktree とサブエージェントで **3 レーンを 4 波（計 12 レーン）走らせました。第 2 波以降は
所有ファイルの衝突がゼロです。**

- **所有ファイルを重ねない。** レーンごとに明示して渡す
- **`docs/product-spec.md` は誰にも編集させない。** 各レーンは文面を報告に書いて返し、
  **取り込む側が版と節番号を付けて 1 本のブランチで入れる。** これで衝突が消えました
- **マイグレーションの連番は先に割り当てる**
- **1 つの継ぎ目を触る 2 issue は同じレーンに畳む**（#28/#29、#148/#153、#164/#165、#149/#166）。
  1 issue = 1 PR は守りつつ、worktree は 1 つにして直列に出させる
- **worktree を消さない。** 再利用すると `node_modules` が残り `npm ci` を省けます
- **食い違いを作った本人へ差し戻す。** 「所有外なので取り込む側で」と言われても、
  **所有ファイルを 1〜3 個足して本人へ返す**ほうが、こちらの指摘より深い直し方が返ります
- **報告を鵜呑みにしない。** 「非コメント行は変更していない」「検査は空振りしない」は
  `diff` と変異で独立に確かめられます。**12 レーン中、申告が誤っていたのは 0 件**でしたが、
  確かめる側が確かめなかった例は 1 件ありました（下記）

### 実物を通すまで、動いているかは分からない

**「プレイ経路は本番で動作」と 2 日にわたって報告していたが、実際には動いていなかった**（#180 / #181）。
根拠にしていたのは **`curl` の 200 と CSP の文字列照合**で、**どちらも CORS を評価しない。**

| 検査 | 通してしまうもの |
|---|---|
| CSP の文字列照合・`curl` | **CORS**（評価しない） |
| `SELF.fetch`（vitest の workers pool） | **HTTP のエンコード**（境界を通らない） |

**どちらも「緑だから正しい」と読める形だった。** 実ブラウザを通して初めて見え、しかも
**1 つ目を直した時点で止めていれば 2 つ目を本番でもう一度踏んでいた**（ブラウザ検査の層が
赤のまま残ったことが、それを防いだ唯一の理由）。

**配信を触ったら `scripts/check-sandbox-browser.sh` を回すこと。** 層 0 は**ブラウザ不要**で
30 秒（`GF_SKIP_BROWSER=1`）、しかも**いちばん見えにくい二重圧縮をそこで捕まえる。**

**そして、同じ根で両方向に間違えた。** 「`Accept-Encoding` の有無でサイズが違う」のを
「Cloudflare の再圧縮だろう」と流して二重圧縮を見逃し、直したあとは正しい本文を
「二重圧縮だ」と誤報した。**どちらも「経路が透過的に展開しうる」ことを勘定に入れていない。**

### 検査そのものを疑うこと

**緑の検査が何も確かめていないことがあります。** #160 で停止対象を IAM ユーザーからロールへ
移したとき、層 3 の検査は識別子を取れずに**赤**になりましたが、層 2 の検査は**消えた output（空）と
消えた環境変数（空）を突き合わせ、空どうしが一致して緑**でした。**確かめていない検査は、
確かめた証拠として読まれるぶん赤より悪い。**

**移動は 3 点セット（許可・停止・検査）です。** 検査の追随漏れは
`scripts/check-tf-output-refs.sh` が機械で見ます。
